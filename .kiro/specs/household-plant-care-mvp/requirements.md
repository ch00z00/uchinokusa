# 要件定義書

## はじめに
uchinokusa は、家庭の室内観葉植物を家族など複数人で一緒に管理するためのネイティブアプリ（iOS / Android）である。既存の植物管理アプリには「無料枠では登録できる株数に上限がある」「複数人で管理を共有できない、または有料」という課題があり、本MVPはこれを解決する。

MVPでは次の2つを中心に提供する。
- **コア機能**：植物の登録、お手入れのスケジュール、リマインダー、ワンタップでの記録、履歴、メモ、植物ごとのカレンダー
- **共有機能**：複数の世帯への所属、招待、権限、誰が作業したかの記録、リアルタイム同期、完了通知

あわせて、購入日をもとにした植え替えの簡易レコメンドと、園芸店を探すための地図アプリ連携を提供する。

お手入れは「何をやるべきか」と同じくらい「今日は何をやらないべきか」が重要である（水やりや肥料はタイミングが大切なため）。また、最終的な判断を植物の状態を見たユーザーに委ねる場面もある。そこで、タスクには実行条件を、記録にはスキップを、提案には「やらない方がよい」「条件つき」の種類を持たせる。

また、フェーズ2以降の天気と連動した助言、AIによる識別・診断、肥料の解説を追加できるよう、植物マスタ・置き場所の情報と、差し替えられる助言の仕組みをMVPの時点で備える。

本書では、システム全体を「uchinokusa」、モバイルアプリを「uchinokusa アプリ」、サーバー側を「uchinokusa API」と表記する。

### 用語
- **世帯**：植物と管理メンバーをまとめる単位（例：自分の家、実家、友人の家）。植物は必ずいずれか1つの世帯に属し、ユーザーは複数の世帯に所属できる。
- **メンバー**：世帯に参加しているユーザー。ロールは「オーナー」「編集者」「閲覧者」のいずれか。
- **お手入れタスク**：植物ごと・種類（水やり、肥料、植え替え、剪定、その他）ごとに設定する、周期つきの作業。
- **実行条件**：タスクを実行するかどうかをユーザーが判断するための条件（例：「土の表面が乾いていたら」）。
- **お手入れ記録**：お手入れタスクについての行動の記録（いつ、誰が、完了またはスキップしたか）。
- **助言プロバイダ**：植物や環境の情報から、提案（レコメンド）を作る差し替え可能な処理。
- **提案の種類**：「実施をすすめる」「やらない方がよい（見送りをすすめる）」「条件つき（もし〜なら〜する）」の3種類。

### 記述ルール
受け入れ基準は EARS の考え方にもとづき、次の型で記述する。
- **〜したとき、** 〔主体〕は〜すること。（イベント駆動）
- **〜の場合、** 〔主体〕は〜すること。（条件）
- **〜の間、** 〔主体〕は〜すること。（状態）
- **〜では、** 〔主体〕は〜すること。（場面・機能の限定）
- 〔主体〕は〜すること。（常に満たすべき要件）

## 要件

### 要件1：アカウントと認証
**目的：** ユーザーは、普段使っているアカウントで簡単にサインインしたい。新しいパスワードを管理せずに使い始められるようにするためである。

#### 受け入れ基準
1. 未サインインのユーザーがアプリを起動したとき、uchinokusa アプリはサインイン画面を表示し、Apple ID または Google アカウントでのサインイン手段を提示すること。
2. ユーザーがサインインに成功したとき、uchinokusa アプリは表示名を設定・確認する画面を表示し、以降はその名前を世帯のメンバーに表示する名前として使うこと。
3. 認証トークンがない、または無効・期限切れの認証トークンのリクエストを受け取ったとき、uchinokusa API はリクエストを拒否し、認証エラーを返すこと。
4. サインイン済みのユーザーがアプリを再起動したとき、uchinokusa アプリはサインイン状態を保ち、再度のサインインを求めずにホーム画面を表示すること。
5. ユーザーがサインアウトしたとき、uchinokusa アプリは端末上のサインイン情報を破棄し、その端末をプッシュ通知の送信先から外すこと。
6. ユーザーがアカウントを削除したとき、uchinokusa はアカウントと個人情報を削除し、所属するすべての世帯から外すこと。
7. アカウントを削除しようとするユーザーが、ほかにメンバーのいる世帯の唯一のオーナーである場合、uchinokusa アプリは削除の前にオーナー権限を別のメンバーへ移すよう求めること。

### 要件2：世帯の作成と管理
**目的：** ユーザーは、自分の家や実家など植物をまとめる「世帯」を作り、複数の世帯に所属したい。それぞれの場所の植物を、それぞれのメンバーと管理できるようにするためである。

#### 受け入れ基準
1. ユーザーが世帯名を入力して世帯を作成したとき、uchinokusa は新しい世帯を作成し、作成したユーザーをその世帯のオーナーにすること。
2. どの世帯にも属していないユーザーがサインインしたとき、uchinokusa アプリは「世帯を作成する」と「招待から参加する」の選択肢を表示すること。
3. uchinokusa は、1人のユーザーが複数の世帯に、世帯ごとに異なるロールで所属できるようにすること。
4. ユーザーが複数の世帯に属している場合、uchinokusa アプリは表示する世帯を切り替える手段を提供し、選択中の世帯の植物・タスクだけを表示すること。
5. オーナーが世帯名を変更したとき、uchinokusa は変更を保存し、世帯のすべてのメンバーに反映すること。
6. オーナーが世帯を削除しようとしたとき、uchinokusa アプリは植物・タスク・記録・メモがすべて消えることを示して確認を求め、確認されたら世帯と関連データを削除すること。
7. オーナー以外のメンバーが世帯から退出したとき、uchinokusa はそのメンバーを世帯から外し、以降はその世帯のデータにアクセスできないようにすること。
8. 世帯の唯一のオーナーが退出しようとし、かつ世帯にほかのメンバーがいる場合、uchinokusa は退出を受け付けず、先にオーナー権限を移すよう求めること。

### 要件3：招待と参加
**目的：** 世帯のオーナーは、招待リンクやQRコードで家族や友人を招待したい。招待された人がすぐに同じ世帯へ参加できるようにするためである。

#### 受け入れ基準
1. オーナーが付与するロール（編集者または閲覧者）を選んで招待を作成したとき、uchinokusa は有効期限つきの招待リンクと、同じ内容のQRコードを発行すること。
2. オーナーが招待リンクを共有するとき、uchinokusa アプリは端末標準の共有機能（メッセージアプリなど）で招待リンクを送れるようにすること。
3. サインイン済みのユーザーが有効な招待リンクを開いたとき、または有効なQRコードを読み取ったとき、uchinokusa アプリは世帯名と付与されるロールを表示して参加の確認を求め、確認されたらユーザーを指定のロールで世帯に追加すること。
4. 未サインインのユーザーが招待リンクを開いたとき、uchinokusa アプリはサインインを求め、サインイン後に同じ招待の参加確認画面へ進むこと。
5. 招待が期限切れ、または取り消し済みの場合、uchinokusa は参加を受け付けず、招待が無効であることを表示すること。
6. すでにメンバーであるユーザーが同じ世帯の招待を開いた場合、uchinokusa は重複して追加せず、すでに参加済みであることを表示すること。
7. オーナーが有効な招待を取り消したとき、uchinokusa はその招待をただちに無効にすること。
8. 新しいメンバーが世帯に参加したとき、uchinokusa はオーナーに参加を通知すること。

### 要件4：ロールと権限
**目的：** 世帯のオーナーは、メンバーごとにできる操作を分けたい。見るだけのメンバーが誤ってデータを変えないようにするためである。

#### 受け入れ基準
1. uchinokusa は、ロールごとに次の操作を許可すること：オーナーはすべての操作、編集者は植物・置き場所・タスク・記録・メモの作成・編集・削除と記録の実行、閲覧者は閲覧と自分の通知設定の変更のみ。
2. 世帯の管理操作（世帯名の変更、世帯の削除、招待の作成・取り消し、メンバーのロール変更・削除、オーナー権限の移譲）では、uchinokusa はオーナーにだけ実行を許可すること。
3. リクエストしたユーザーのロールで許可されていない操作を受け取ったとき、uchinokusa API は操作を拒否し、権限エラーを返すこと。
4. ユーザーが所属していない世帯のデータへのリクエストを受け取ったとき、uchinokusa API はデータを返さずにリクエストを拒否すること。
5. ユーザーが閲覧者として世帯を表示している間、uchinokusa アプリは編集・記録の操作を表示しない、または無効にすること。
6. オーナーがメンバーのロールを変更したとき、uchinokusa は変更をただちに反映し、そのメンバーの端末で表示中の画面の操作可否も更新すること。
7. オーナーがメンバーを世帯から削除したとき、uchinokusa はそのメンバーの世帯へのアクセスをただちに止め、そのメンバーが過去に作った記録は作業者名を残したまま保持すること。
8. オーナーがオーナー権限を別のメンバーに移したとき、uchinokusa は移した先のメンバーをオーナーにし、元のオーナーを編集者にすること。

### 要件5：植物の登録と管理
**目的：** 編集者以上のメンバーは、世帯の植物を上限なく登録・編集したい。家にあるすべての植物を管理できるようにするためである。

#### 受け入れ基準
1. 編集者以上のメンバーが植物名を入力して登録したとき、uchinokusa は選択中の世帯に植物を登録すること。
2. uchinokusa は、植物の登録・編集で、名前（必須）、種類（植物マスタから選ぶか自由入力、任意）、置き場所（任意）、購入日・お迎え日（任意）を入力できるようにすること。
3. uchinokusa は、1つの世帯に登録できる植物の数に、プランによる上限を設けないこと。
4. メンバーが植物一覧を開いたとき、uchinokusa アプリは選択中の世帯の植物を、名前・置き場所・次のお手入れ予定日とともに一覧表示すること。
5. メンバーが植物一覧を置き場所で絞り込んだとき、または名前で検索したとき、uchinokusa アプリは条件に合う植物だけを表示すること。
6. 編集者以上のメンバーが植物の情報を編集したとき、uchinokusa は変更を保存し、世帯のメンバーに反映すること。
7. 編集者以上のメンバーが植物を削除しようとしたとき、uchinokusa アプリはタスク・記録・メモも削除されることを示して確認を求め、確認されたら植物と関連データを削除すること。
8. 編集者以上のメンバーが植物を「枯れた・手放した」としてアーカイブしたとき、uchinokusa はその植物を通常の一覧とリマインダーの対象から外し、記録とメモは閲覧できる状態で残すこと。

### 要件6：植物マスタ（将来の助言のための植物情報）
**目的：** ユーザーは、植物の種類を選ぶと、その種類の性質が紐づくようにしたい。おすすめのお手入れ周期や、今後の助言に活かせるようにするためである。

#### 受け入れ基準
1. uchinokusa は、植物の種類ごとの情報として、和名・学名・別名、好む光の量、耐寒性（最低温度の目安）、好む湿度、風通しの必要性、水やりの量の傾向、屋外に出せるかを保持できるようにすること。
2. ユーザーが植物の登録・編集で種類を検索したとき、uchinokusa アプリは和名・学名・別名で植物マスタを検索し、候補を表示すること。
3. 探している種類が植物マスタにない場合、uchinokusa は種類を自由入力できるようにし、マスタと紐づかない植物としても登録・管理できるようにすること。
4. マスタと紐づく植物にお手入れタスクを設定するとき、マスタに推奨周期や推奨の実行条件がある場合、uchinokusa アプリはそれらを初期値として示すこと。
5. uchinokusa は、MVPの時点で主要な室内観葉植物の植物マスタを初期データとして用意すること。
6. uchinokusa は、植物マスタを世帯のデータとは別の、全ユーザー共通のデータとして管理すること。

### 要件7：置き場所
**目的：** 編集者以上のメンバーは、植物を置いている場所とその環境を登録したい。置き場所ごとに植物を把握でき、将来は天気や日差しに応じた助言を受けられるようにするためである。

#### 受け入れ基準
1. 編集者以上のメンバーが置き場所名（例：「リビングの南窓」）を入力して作成したとき、uchinokusa は選択中の世帯に置き場所を登録すること。
2. uchinokusa は、置き場所の環境情報として、室内か屋外か、窓の向き（東西南北など）、窓からの距離の目安、遮光の有無（レースカーテンなど）を任意で入力できるようにすること。
3. 編集者以上のメンバーが置き場所の情報を編集したとき、uchinokusa は変更を保存し、その置き場所に紐づくすべての植物に反映すること。
4. 植物が紐づいている置き場所を削除しようとした場合、uchinokusa アプリは紐づいている植物の数を示して確認を求め、確認されたら置き場所を削除し、それらの植物を「置き場所未設定」にすること。
5. uchinokusa は、世帯のおおよその地域（都道府県・市区町村レベル）を任意で登録できるようにすること。

### 要件8：お手入れスケジュールと実行条件
**目的：** 編集者以上のメンバーは、植物ごと・作業の種類ごとに周期と実行条件を設定したい。次にいつ何をすればよいか、またそのときに実行すべきかどうかの判断材料がわかるようにするためである。

#### 受け入れ基準
1. 編集者以上のメンバーが植物に、種類（水やり・肥料・植え替え・剪定・その他）と周期（日数・週数・月数）を指定してお手入れタスクを追加したとき、uchinokusa はタスクを登録し、次回の予定日を計算して設定すること。
2. uchinokusa は、1つの植物に種類の異なる複数のお手入れタスクを設定できるようにすること。
3. タスクの種類が「その他」の場合、uchinokusa は作業名を自由入力で設定できるようにすること。
4. uchinokusa は、お手入れタスクに、周期のほか、初回の予定日と任意のメモ（例：「底から流れるまでたっぷり」）を設定できるようにすること。
5. uchinokusa は、お手入れタスクに任意の実行条件（例：「土の表面が乾いていたら」「葉が垂れていたら」）を設定できるようにすること。
6. uchinokusa は、お手入れタスクの周期を、季節（春・夏・秋・冬）ごとに異なる値で設定できるようにすること。
7. 季節が変わったとき、タスクに季節ごとの周期が設定されている場合、uchinokusa は新しい季節の周期で次回の予定日を計算すること。
8. 編集者以上のメンバーがタスクの周期、実行条件、または次回の予定日を変更したとき、uchinokusa は新しい値で予定を更新し、世帯のメンバーに反映すること。
9. 編集者以上のメンバーがお手入れタスクを一時停止したとき、uchinokusa は再開されるまで、そのタスクを予定・リマインダーの対象から外すこと。
10. 編集者以上のメンバーがお手入れタスクを削除したとき、uchinokusa はタスクを削除し、そのタスクの過去の記録は履歴として残すこと。

### 要件9：今日やること一覧
**目的：** メンバーは、今日やるべきこと・今日はやらない方がよいことを一覧で見たい。世帯全体の今日のお手入れの判断が、ひと目でつくようにするためである。

#### 受け入れ基準
1. メンバーがホーム画面を開いたとき、uchinokusa アプリは選択中の世帯で、予定日が今日以前の未完了タスクを一覧表示すること。
2. uchinokusa アプリは、今日やること一覧の各項目に、植物名、置き場所、作業の種類、予定日、設定されていれば実行条件を表示すること。
3. 予定日を過ぎた未完了のタスクがある場合、uchinokusa アプリはそのタスクを期限切れとして区別し、何日過ぎているかを表示すること。
4. 今日のタスクに対して助言プロバイダが「やらない方がよい」提案を出している場合、uchinokusa アプリはそのタスクに「今日は不要」などの表示と理由を添え、実施をすすめるタスクと区別して表示すること。
5. メンバーが一覧の表示を切り替えたとき、uchinokusa アプリはタスクを置き場所ごと、または作業の種類ごとにまとめて表示すること。
6. 今日の未完了タスクが1件もないとき、uchinokusa アプリは今日の作業がないことと、直近の次の予定を表示すること。
7. 世帯の別のメンバーが一覧のタスクを完了またはスキップしたとき、uchinokusa アプリはその項目を一覧から外し、対応したメンバー名を表示すること。

### 要件10：ワンタップ記録・スキップと次回予定の自動計算
**目的：** 編集者以上のメンバーは、お手入れをしたこと、または今回はしないと判断したことをワンタップで記録したい。行動の実績にもとづいて、次の予定が自動で決まるようにするためである。

#### 受け入れ基準
1. 編集者以上のメンバーがタスクの完了ボタンを押したとき、uchinokusa は実施日時・作業の種類・実施したメンバーを記録し、タスクを完了状態にすること。
2. タスクが完了として記録されたとき、uchinokusa は実施日を起点に、その時点で有効な周期で次回の予定日を計算して設定すること。
3. 編集者以上のメンバーが記録時に実施日を過去の日付に変更したとき、uchinokusa は指定された実施日で記録し、その日を起点に次回の予定日を計算すること。
4. 編集者以上のメンバーが記録の直後に取り消したとき、uchinokusa は記録を取り消し、タスクの予定日を記録前の状態に戻すこと。
5. 編集者以上のメンバーが予定日より前にタスクを完了したとき、uchinokusa は記録を受け付け、実施日を起点に次回の予定日を計算し直すこと。
6. 編集者以上のメンバーがタスクを「今回はスキップ」したとき、uchinokusa はスキップとして記録し、作業をしたことにはしないこと。
7. スキップするとき、uchinokusa アプリは任意で理由（例：「土がまだ湿っている」「天気が悪い」「株が弱っている」「その他（自由入力）」）を選べるようにすること。
8. スキップが記録されたとき、uchinokusa はタスクを未完了のまま、次回の確認日として翌日以降の日（初期値：翌日）を設定し、ユーザーが確認日を変更できるようにすること。
9. 編集者以上のメンバーが複数のタスクを選んでまとめて完了したとき、uchinokusa は選んだすべてのタスクを、それぞれ完了として記録すること。

### 要件11：重複作業の防止とリアルタイム同期
**目的：** 世帯のメンバーは、家族の作業がすぐに自分の画面に反映されてほしい。同じ植物に二重で水やりするのを防げるようにするためである。

#### 受け入れ基準
1. メンバーが植物・置き場所・タスク・記録・メモ・メンバー情報を作成・更新・削除したとき、uchinokusa は同じ世帯の画面を開いているほかのメンバーの端末に、数秒以内に変更を反映すること。
2. 完了しようとしたタスクを、同じ予定の回にすでに別のメンバーが完了している場合、uchinokusa は重複して記録せず、誰がいつ完了したかを表示すること。
3. 重複の表示を受けたメンバーが、それでも追加で記録することを明示的に選んだとき、uchinokusa は追加の記録として保存すること。
4. 複数のメンバーがほぼ同時に同じタスクを完了しようとしたとき、uchinokusa API は最初に受け付けた1件だけを完了の記録とし、ほかのリクエストには重複であることを返すこと。
5. アプリがバックグラウンドから復帰したとき、または通信が回復したとき、uchinokusa アプリは最新のデータを取得して表示を更新すること。
6. 通信ができない状態で記録の操作が行われた場合、uchinokusa アプリは記録できなかったことを表示し、通信回復後の再実行を促すこと。

### 要件12：お手入れの履歴
**目的：** メンバーは、植物ごとに、いつ誰が何をしたか（しなかったか）を振り返りたい。お手入れの状況を家族で正しく共有できるようにするためである。

#### 受け入れ基準
1. メンバーが植物の詳細画面で履歴を開いたとき、uchinokusa アプリはその植物の記録を新しい順に、日時・作業の種類・完了かスキップか（スキップの場合は理由）・対応したメンバー名とともに表示すること。
2. メンバーが履歴を作業の種類で絞り込んだとき、uchinokusa アプリは選んだ種類の記録だけを表示すること。
3. uchinokusa アプリは、履歴に作業の種類ごとの最終実施日を表示すること。
4. 編集者以上のメンバーが過去の記録を編集・削除したとき、uchinokusa は変更を保存し、それが最新の実施分であれば、タスクの次回予定日を計算し直すこと。
5. uchinokusa は、世帯から外れたメンバーの過去の記録も、作業者名を残したまま表示すること。

### 要件13：植物ごとのテキストメモ
**目的：** 編集者以上のメンバーは、植物の成長や状態をテキストで記録したい。写真がなくても、変化や気づきを家族と共有できるようにするためである。

#### 受け入れ基準
1. 編集者以上のメンバーが植物の詳細画面でメモを入力して保存したとき、uchinokusa は作成日時と作成したメンバーとともに、その植物のメモとして保存すること。
2. メンバーが植物のメモ一覧を開いたとき、uchinokusa アプリはその植物のメモを新しい順に、作成日時・作成者とともに表示すること。
3. メモの作成者またはオーナーがメモを編集・削除したとき、uchinokusa は変更を保存し、編集されたメモには編集済みであることを表示すること。
4. メモの本文が空、または上限文字数を超えている場合、uchinokusa アプリは保存せず、入力内容の修正を促すこと。
5. uchinokusa は、MVPではメモに画像を添付する機能を提供しないこと。

### 要件14：植物ごとのカレンダー表示
**目的：** メンバーは、植物ごとにお手入れの実績と予定をカレンダーで見たい。水やりの間隔や今後の予定を直感的に把握できるようにするためである。

#### 受け入れ基準
1. メンバーが植物の詳細画面でカレンダーを開いたとき、uchinokusa アプリは月単位のカレンダーに、その植物の過去の記録（完了・スキップ）と今後の予定日を表示すること。
2. uchinokusa アプリは、カレンダー上で作業の種類ごとに区別できる表示（アイコンや色など）を使い、完了・スキップ・予定の違いがわかるようにすること。
3. uchinokusa アプリは、カレンダー上でメモを書いた日を示すこと。
4. メンバーがカレンダーの日付を選んだとき、uchinokusa アプリはその日の記録（対応したメンバーを含む）、予定、メモの一覧を表示すること。
5. メンバーが前月・翌月へ移動したとき、uchinokusa アプリは移動先の月の記録と予定を表示すること。

### 要件15：リマインダー通知
**目的：** メンバーは、予定日にお手入れを通知で知らせてほしい。アプリを開かなくても、やることを忘れないようにするためである。

#### 受け入れ基準
1. 世帯に予定日が今日以前の未完了タスクがあり、かつメンバーのリマインダー通知が有効なとき、uchinokusa はメンバーが設定した時刻に、今日のタスク件数と内容の概要をプッシュ通知で送ること。
2. uchinokusa は、リマインダーを1日1回、世帯ごとにまとめた通知として送り、タスクごとに個別の通知を出さないこと。
3. メンバーが通知設定でリマインダーの有効・無効や時刻を変更したとき、uchinokusa は以降のリマインダーに変更を反映すること。
4. 送信時刻までにその日のタスクがすべて完了またはスキップされている場合、uchinokusa はその日のリマインダーを送らないこと。
5. メンバーがリマインダー通知を開いたとき、uchinokusa アプリは対象の世帯の今日やること一覧を表示すること。
6. 端末の通知許可がオフになっている場合、uchinokusa アプリは通知設定画面で通知が届かない状態であることを示し、端末の設定を開く導線を表示すること。
7. uchinokusa は、リマインダーの日付と送信時刻を、メンバーの端末のタイムゾーンで判定すること。
8. uchinokusa は、世帯の閲覧者にも、通知設定に応じてリマインダーを送ること。

### 要件16：タスク完了通知とメンバー別の通知設定
**目的：** メンバーは、家族がお手入れしたことを知りたいが、通知の量は自分で選びたい。状況を把握しつつ、通知に煩わされないようにするためである。

#### 受け入れ基準
1. メンバーがタスクを完了として記録したとき、ほかのメンバーの完了通知が有効であれば、uchinokusa はそのメンバーに、作業者名・植物名・作業の種類を含むプッシュ通知を送ること。
2. uchinokusa は、作業した本人には完了通知を送らないこと。
3. uchinokusa は、完了通知の受け取りの有無をメンバーごと・世帯ごとに設定できるようにし、初期値を「受け取る」にすること。
4. 1人のメンバーが短時間に複数のタスクを完了したとき、uchinokusa はそれらの完了通知を1件にまとめて送ること。
5. メンバーが完了通知を開いたとき、uchinokusa アプリは対象の植物の詳細画面を表示すること。
6. 記録が直後に取り消され、その記録の完了通知がまだ送られていない場合、uchinokusa はその完了通知を送らないこと。
7. uchinokusa は、スキップの記録については完了通知を送らないこと。

### 要件17：植え替えの簡易レコメンド
**目的：** 植物を買ったばかりのメンバーは、植え替えに適した時期を提案してほしい。買ったばかりの植物を、株を傷めにくい時期に植え替えられるようにするためである。

#### 受け入れ基準
1. 編集者以上のメンバーが購入日・お迎え日つきで植物を登録したとき、その植物に植え替えタスクがなければ、uchinokusa は植え替えの予定日の提案を作り、ユーザーに示すこと。
2. uchinokusa は、植え替えの提案日を、購入日から慣らし期間（初期値：14日）を過ぎた日以降で、最も早い植え替えの適期内の日にすること。
3. uchinokusa は、植え替えの適期を春〜初夏（初期値：4月〜6月）と初秋（初期値：9月）とし、真夏（7月〜8月）と真冬（12月〜2月）を提案日にしないこと。
4. メンバーが提案を採用したとき、uchinokusa は提案日を予定日とする植え替えタスクを作成すること。
5. メンバーが提案日を変更して採用したとき、uchinokusa は変更後の日を予定日とする植え替えタスクを作成すること。
6. メンバーが提案を見送ったとき、uchinokusa は植え替えタスクを作成せず、同じ植物に同じ提案を自動で繰り返し示さないこと。
7. uchinokusa は、提案とあわせて提案日を選んだ理由（例：「慣らし期間のあと、真夏を避けた最初の適期です」）を表示すること。
8. メンバーが植え替えタスクの予定日を真夏または真冬に設定しようとした場合、uchinokusa アプリは「この時期の植え替えは株を傷めやすい」という、やらない方がよいことの助言を表示すること（設定自体は妨げない）。
9. uchinokusa は、植え替えの提案を、差し替え可能な助言プロバイダの1つとして作ること。

### 要件18：園芸店を探す（地図アプリ連携）
**目的：** メンバーは、近くの園芸店をすぐに探したい。土や肥料、植物を買いに行けるようにするためである。

#### 受け入れ基準
1. メンバーが「近くの園芸店を探す」を選んだとき、uchinokusa アプリは端末の地図アプリを開き、「園芸店」での検索結果を表示すること。
2. 端末で地図アプリを開けない場合、uchinokusa アプリはブラウザで地図サービスの検索結果を開くこと。
3. uchinokusa アプリは、この機能のためにユーザーの位置情報を自身で取得・保存しないこと。

### 要件19：将来の拡張に備えた構造
**目的：** 開発者は、フェーズ2以降の機能を、既存の機能を大きく作り直さずに追加したい。天気と連動した助言やAIの機能を、段階的に加えられるようにするためである。

#### 受け入れ基準
1. uchinokusa は、提案を作る処理を、植物・植物マスタ・置き場所・世帯の地域・日付・過去の記録などを受け取って提案を返す、共通の仕組み（助言プロバイダ）として扱うこと。
2. uchinokusa は、提案の種類として「実施をすすめる」「やらない方がよい」「条件つき（もし〜なら〜する）」の3つを表現できるようにすること。
3. uchinokusa は、提案に、対象（植物・タスク）、種類、内容、理由、有効期間を持たせること。
4. 条件つきの提案を表示するとき、uchinokusa アプリは条件と、その条件にあてはまる場合の行動をあわせて示し、あてはまるかどうかの判断をユーザーに委ねること。
5. uchinokusa は、新しい助言プロバイダ（例：天気と連動した「今日は水やり不要」の助言）を、既存の提案の表示・採用・見送りの流れを変えずに追加できるようにすること。
6. uchinokusa は、提案ごとに、提案元の助言プロバイダ、提案内容、理由、ユーザーの対応（採用・見送り）を記録すること。
7. uchinokusa は、スキップの理由を、将来の助言の改善に使える形で保存すること。
8. uchinokusa は、植物マスタ・置き場所・世帯の地域の項目を、MVPの画面で使わない項目も含めて保存できるようにすること。
9. uchinokusa は、アプリとAPIの間の取り決めを、互換性を保ったまま項目を追加できる形にすること。

### 要件20：非機能要件（セキュリティ・信頼性・使いやすさ）
**目的：** ユーザーは、家族のデータが安全に、ストレスなく扱われてほしい。安心して毎日使い続けられるようにするためである。

#### 受け入れ基準
1. uchinokusa は、アプリとAPIの間の通信をすべて暗号化された経路（HTTPS / WSS）で行うこと。
2. uchinokusa API は、すべての操作で、認証済みのユーザーが対象の世帯のメンバーであるか、ロールが操作を許可しているかを、サーバー側で検証すること。
3. uchinokusa は、招待リンクに推測されにくい識別子を使うこと。
4. 通常の通信環境でメンバーが一覧や詳細を開いたとき、uchinokusa アプリは2秒以内に内容を表示すること。
5. 編集者以上のメンバーが完了ボタンを押したとき、uchinokusa アプリは押した直後に完了したことを画面に反映し、サーバーで記録できなかった場合は元に戻して知らせること。
6. uchinokusa アプリは、iOS と Android の両方で同じ機能を提供すること。
7. uchinokusa アプリは、画面の表示文言を日本語で提供し、将来ほかの言語を追加できる構造にすること。
8. uchinokusa は、世帯のデータを定期的にバックアップし、障害時に復元できるようにすること。

## MVPの対象外（今後の検討事項）
- **オフライン時の記録の一時保存**：通信できない間の記録を端末に一時保存し、通信が戻ったら送る。
- **通知の細かい設定**：まとめずにすべてリアルタイムで受け取るなど、運用しながら検討する。
- **天気と連動した助言**（フェーズ2）：Open-Meteo などの天気情報 × 植物マスタ × 置き場所から、「今日は水やり不要」「窓際から離して」などを提案する。
- **AIによる植物の識別・病害虫の診断**
- **肥料・活力剤の解説**
- **アプリ内での園芸店の検索**
- **写真の添付・成長写真の比較**
