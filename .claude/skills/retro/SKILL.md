# デザインの振り返り（retro）

デザインの試行錯誤から、ユーザーの好みを抜き出して残す。次のデザインの作業で、最初の案からその好みに沿えるようにするのが目的。

## 手順
1. **対象を決める**：この会話のうち、前回の振り返り（`docs/design/retro/` の最新のファイル）より後の、デザインに関するやり取りを見る。対象の画面・部品を確かめる
2. **拾う**：次のことを、ユーザーの言葉をそのまま引用して拾う
   - 出した案（何を・なぜそうしたか）
   - ユーザーの反応：採用した・却下した・直すように言った。その理由（言っていなければ、推測せずに「理由は言われていない」とする）
   - 最後に決まった形
3. **好みを抜き出す**：次にも効く好みを、短い1文にする（例：「カードには影を付けず、背景の色の差で分ける」）
   - ユーザーの反応があったものだけを好みにする。私の推測だけで好みを作らない
   - その画面だけの事情（「この画面は情報が多いので」など）は、好みにせず、記録にだけ残す
   - 色・文字・余白の値が絡むときは、`docs/design/foundations.md` の値（トークン）と突き合わせ、トークンの名前で書く
4. **記録を書く**：`docs/design/retro/YYYY-MM-DD-<主題>.md` に、その回の記録を書く（形は `docs/design/retro/README.md`）
5. **好みの一覧を更新する**：`docs/design/preferences.md` に足す
   - すでにある好みと同じなら、回数を増やし、根拠（記録のファイル名と引用）を足す
   - すでにある好みと食い違うなら、新しいほうにし、古いほうは「改めた」として理由とともに残す（消さない）
6. **昇格の案を出す**：3回以上出てきた好み、またはユーザーが「いつも」「必ず」と言った好みは、`.kiro/steering/design.md`（方針）に入れる案を示す。入れるのは、ユーザーが承認してから
7. **報告する**：今回わかった好みを3〜5行でユーザーに見せ、違っていれば直す

## 決まり
- 書くのはすべて日本語。ユーザーの言葉は言い換えずに引用する
- 好みは「何を・どうする」がわかる具体的な形にする（「おしゃれに」のような、あいまいなものにしない）
- このスキルのファイルと、`docs/design/preferences.md`・`docs/design/retro/` は、アプリ担当のファイル。コミットはパスを指定して行う（`git add <ファイル>` → `git commit -m "..." -- <ファイル>`）
