# デザインの好み

ユーザーのデザインの好みの一覧。デザインの作業（Figma、画面・部品の見た目の実装）の前に読み、最初の案からこれに沿う。
`/retro`（`.claude/skills/retro/SKILL.md`）で、試行錯誤の記録（`docs/design/retro/`）から育てる。3回以上出てきた好みは、`.kiro/steering/design.md` に入れる案を出す。

## 書き方
- 1つの好みを1行にする：`- <好み>（<n>回）— 根拠：retro/<ファイル名>「<ユーザーの言葉>」`
- 食い違う好みが出たら、新しいほうにし、古いほうは「改めた」に移す（理由とともに残す）

## 余白とレイアウト
- 主な画面へ行く入り口（設定など）は、ヘッダーのボタンではなく、下のタブバーに置く（1回）— 根拠：retro/2026-11-20-household-invitation.md「設定は下のフローティングナビゲーションにあるべきでしょ。」

## 部品
- ヘッダーに置く文字のボタン（世帯の切り替えなど）には、背景を付けない（1回）— 根拠：retro/2026-11-20-household-invitation.md「世帯は背景色いらないと思うよ。」
- 一覧の中などに置く操作は、文字だけにせず、枠か背景の色を付けてボタンとわかるようにする（1回）— 根拠：retro/2026-11-20-household-invitation.md「「取り消す」ボタンはアウトラインか背景色がほしいかな。」

## 動き
- 保存などの操作の結果は、ボタンの近くの文字ではなく、画面の下のトースト（`Toast`）で知らせる（1回）— 根拠：retro/2026-11-20-household-invitation.md「保存したときにはスナックバーで結果表示した方が分かりやすい」
- 保存したら、キーボードを閉じて入力のフォーカスを外す（1回）— 根拠：retro/2026-11-20-household-invitation.md「選択のフォーカスが外れない」

## 文言
- 確認のダイアログの決定のボタンは、対象の名前を入れず、動詞だけにする（例：「削除する」）（1回）— 根拠：retro/2026-11-20-household-invitation.md「「世帯を削除する」ではなく「削除する」のみでいいです」
