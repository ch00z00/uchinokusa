# 0002. 一般的なアイコンは OS のシンボル（iOS は SF Symbols）を使い、アプリ固有の概念のアイコンだけをオリジナルで作る

- 状態：採用
- 日付：2026-11-01
- 関連：`docs/design/decisions/0001`、`docs/design/foundations.md`（4章 アイコン）、`.kiro/steering/design.md`

## 背景
- 0001 で、OS に共通の UI は OS の標準部品に任せ、アプリ固有の UI はデザインシステムで作ると決めた。アイコンでも同じ線引きが必要になる
- SF Symbols は種類が多く、文字の大きさや太さに合わせて自然に調整され、見た目もクリーンで、iPhone の利用者になじみがある
- 一方で、「水やり」「植え替え」「今日は不要」のような uchinokusa 固有の概念には、ぴったりのシンボルがない
- デザイナー（開発者の妻）に、アプリ固有のアイコンだけを依頼できる
- SF Symbols は、Apple のプラットフォームで動くアプリの UI にだけ使える（Xcode と Apple SDK の使用許諾）。Android のアプリでは使えない

## 検討した案
| 案 | 内容 | 評価 |
|---|---|---|
| A. クロスプラットフォームのアイコンセット | Phosphor、Lucide などを両方の OS で使う | 統一はできるが、iOS の標準の見た目から少し外れる。固有の概念のアイコンはやはり足りない |
| B. OS のシンボルだけを使う | iOS は SF Symbols、Android は Material Symbols | 固有の概念を表すアイコンがなく、作業の種類の見分けが弱くなる |
| **C. 一般的なものは OS のシンボル、固有の概念はオリジナル** | 0001 の2つの層と同じ線引きにする | **採用** |

## 決定
1. **一般的なアイコン**（追加・検索・共有・設定・ゴミ箱・カレンダーなど）は OS の層として扱う
   - iOS：SF Symbols
   - Android：Material Symbols（Rounded。SF Symbols の柔らかい線に近い）
   - 同じ意味のアイコンを、OS ごとに対応表で決める（`foundations.md` の4章）
2. **アプリ固有の概念のアイコン**（作業の種類、提案の種類など）は、オリジナルで作り、両方の OS で同じものを使う
   - SF Symbols と並んでも違和感がないよう、線の太さ・角の丸み・余白を SF Symbols の Regular に合わせる
   - 1色（形だけ）で作り、色はコードのトークンで付ける
3. **SF Symbols を Android 版、ロゴ、宣伝の素材に使わない**（使用許諾の範囲外のため）。アプリのアイコン（ホーム画面のアイコン）にも使わない

## 理由
- 一般的なアイコンを OS に任せれば、作る数が大幅に減り、OS のアップデートにも追従できる
- 固有の概念だけをオリジナルにすると、uchinokusa らしさが一番目に触れる場所（今日やること、カレンダー）に集中する
- 0001 と同じ線引きなので、Figma・コードのどちらでも「自作するか、OS に任せるか」を迷わない

## トレードオフ
- 一般的なアイコンは、iOS と Android で形が少し違う
- オリジナルのアイコンは、SF Symbols のように文字の太さに合わせて自動で変わらない。使う大きさ（`foundations.md` に記載）で見え方を確認する必要がある
- デザイナーの作業が必要になる。そろうまでは、仮のアイコン（SF Symbols の近いもの）で進める
