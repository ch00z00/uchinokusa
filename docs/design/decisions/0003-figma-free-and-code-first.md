# 0003. Figma は無料プランで使い、デザインシステムと主な画面のおおまかな見た目だけを作る。細部は実装しながら調整する

- 状態：採用
- 日付：2026-11-01
- 関連：`docs/design/design-to-implementation.md`、`docs/design/foundations.md`、`.kiro/steering/design.md`

## 背景
- 当初の流れ（`design-to-implementation.md` の初版）は、Figma MCP で Claude Code が Figma に下書きを書き込み、実装のときに Figma を読み取る前提だった
- Figma の無料プラン（Starter）では、Figma MCP の読み取りが月に数回までに制限され、Figma への書き込みには有料の Full シートが必要になる。変数のモード（ライトとダーク）も1つに制限される可能性がある
- uchinokusa は個人開発で、利用者はまず開発者の家族である。デザインツールに継続的な費用はかけない
- デザインの確認は、開発者と、デザイナーである妻の2人で行える

## 検討した案
| 案 | 内容 | 評価 |
|---|---|---|
| A. 有料プラン（Full シート）で Figma MCP を使う | Claude が Figma に書き込み、実装で読み取る | 流れはなめらかだが、個人開発に継続的な費用がかかる |
| B. 無料プランで、すべての画面を Figma で作り込む | 全画面・全状態を人が描く | 41画面と状態の組み合わせを人が描くのは重く、実装より先にデザインが詰まる |
| **C. 無料プランで、デザインシステムと主な画面だけを作る** | 細部は実装しながら、実機で調整する | **採用** |

## 決定
1. **Figma は無料プランで使う。Figma MCP には頼らない**
   - Claude Code は Figma に書き込まない。Figma の読み取りも前提にしない
2. **Figma で作るのは、デザインシステムと、主な画面のおおまかな見た目だけ**
   - デザインシステム：`foundations.md` の色・文字・余白、アプリの層の部品（TaskCard など）とその状態
   - 主な画面：今日やること・植物の一覧・植物の詳細・タスクの作成・サインインなど、ほかの画面の手本になるもの
   - すべての画面・すべての状態は描かない
3. **トークンの値の正は、リポジトリの `docs/design/foundations.md` に置く**
   - Figma で値を変えたら、`foundations.md` を直してからコードに反映する
4. **Claude Code への引き継ぎは、Figma から書き出した画像で行う**
   - 画像は `docs/design/screens/` に、画面 ID の名前で置く（例：`TODAY-01.png`）
   - Claude Code は画像を読めるので、`screen-inventory.md`（何を出すか）、`foundations.md`（どの値を使うか）、画像（どう並べるか）の3つを見て実装する
   - 画像がない画面は、デザインシステムと、似た画面の画像にならって実装する
5. **細部の見た目は、実装しながら実機で調整する**
   - 開発者と妻がシミュレーターや実機で確認し、気になった点を直す
   - 細部の見た目の正はコード（実機の画面）とし、Figma をすべて追従させることはしない
   - ただし、トークンの値や部品の形が変わる場合は、`foundations.md` と Figma のデザインシステムにも反映する

## 理由
- 費用をかけずに、デザインの判断に必要な部分（デザインシステムと手本の画面）だけを、人が確認できる
- 細部は実機で見た方が判断しやすい（文字の大きさ、押しやすさ、ダークモード、Dynamic Type）
- 値の正をリポジトリに置けば、Figma のプランに関係なく、Claude Code がいつでも読める
- デザインシステムがあれば、描いていない画面も同じ見た目のルールで実装できる

## トレードオフ
- Figma と実装の画面は、細部でずれていく。Figma は「デザインシステムと方向性の資料」と位置づけ、最新の見た目の資料としては扱わない
- 画像からの実装は、Figma MCP の読み取りより情報が少ない（正確な余白の値などは分からない）。値は `foundations.md` のトークンから選ぶことで補う
- Figma の無料プランでダークモードの変数を作れない場合、ダークモードは実機で確認する

## 補足
- 将来、デザインを作り込む必要が出たり、Figma の有料プランを使うことになったりしたら、この記録を置き換えて、Figma MCP を使う流れを検討し直す
