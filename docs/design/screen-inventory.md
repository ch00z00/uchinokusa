# 画面・コンポーネント・挙動の洗い出し（MVP）

- 作成日：2026-10-31
- 目的：バックエンドの実装と並行してデザインを進めるために、アプリに必要な画面・部品・挙動・状態を一覧にする
- 出典：`.kiro/specs/household-plant-care-mvp/` の requirements.md（要件）、design.md（設計）、tasks.md（タスク 14〜19）、`api/openapi.yaml`、`server/db/migrations/00001_init.sql`
- 表記：
  - 「要件 10-4」は requirements.md の要件10の受け入れ基準4を指す
  - 画面の ID（例：`TODAY-01`）は Figma のフレーム名などにそのまま使える
  - 仕様に書かれていないが、デザインの段階で決める必要があることは **【未決】** とし、最後の「未決事項」にまとめる

## 1. 前提：デザインに効いてくるルール

| ルール | 画面への影響 | 出典 |
|---|---|---|
| ロールは3つ：オーナー、編集者、閲覧者 | 閲覧者には、記録・編集のボタンを **出さない、または無効にする**。オーナーだけが世帯の管理（名前の変更・招待・メンバー管理・削除）をできる | 要件4 |
| ロールは世帯ごとに違う | 世帯を切り替えると、出せるボタンが変わる | 要件2-3、4-5 |
| 変更はほかの家族の画面に数秒で反映される | どの画面も、表示中に内容が変わることがある（項目が消える・増える） | 要件11-1 |
| 完了はワンタップ、すぐに画面に反映する | 押した直後に一覧から消え、「取り消し」を数秒出す。失敗したら元に戻して知らせる | 要件10-1、20-5 |
| 「やらない」も示す | タスクには「今日は不要」「条件つき」の表示がある | 要件9-4、19-4 |
| 通知は控えめ | 通知は世帯ごとに1日1回のまとめと、完了通知（まとめて送る）だけ | 要件15、16 |
| 写真はない | 植物の画像やアイコンは、作業の種類のアイコンや色で表現する（植物の写真の枠を作らない） | 要件13-5 |
| 文言は日本語、ほかの言語を追加できる構造 | 文字数の長い言語でも崩れない余白にしておく | 要件20-7 |
| iOS / Android で同じ機能 | 両 OS の標準の部品（日付の選択、共有シートなど）の見た目の違いを考慮する | 要件20-6 |
| 対象には IT に詳しくない親世代も含む | 文字の大きさ、押しやすいボタンの大きさ、確認の分かりやすさを重視する | product.md |

## 2. 画面遷移の全体像

Expo Router の構成（`(auth)`、`(tabs)/today`、`(tabs)/plants`、`plants/[id]`、`settings`、`invite/[token]`）をもとにした案。

```
起動（BOOT-01）
 ├─ 未サインイン ──> サインイン（AUTH-01）
 │                    └─ 成功 ──> 表示名の設定（AUTH-02）※初回のみ
 │                                 └─> 世帯がない ──> はじめての選択（ONB-01）
 │                                                    ├─ 世帯を作成（ONB-02）
 │                                                    └─ 招待から参加（INV-10 コード入力 / INV-11 QR読み取り）
 └─ サインイン済み ──> メイン（タブ）
        │
        ├─ [タブ] 今日（TODAY-01）
        │     ├─ スキップ（TODAY-03）／実施日を変えて記録（TODAY-04）
        │     ├─ 重複の確認（TODAY-05）
        │     └─ まとめて完了（TODAY-06）
        │
        ├─ [タブ] 植物（PLANT-01）
        │     ├─ 植物の登録（PLANT-02）── 種類の検索（PLANT-03）
        │     │     └─ 植え替えの提案（PLANT-04）
        │     ├─ アーカイブした植物（PLANT-05）
        │     └─ 植物の詳細（PLANT-10）
        │           ├─ 概要・タスク ── タスクの作成・編集（TASK-01）
        │           ├─ 履歴（PLANT-11）── 記録の編集（PLANT-12）
        │           ├─ メモ（PLANT-13）── メモの作成・編集（PLANT-14）
        │           └─ カレンダー（PLANT-15）── 日付の詳細（PLANT-16）
        │
        └─ [タブ] 設定（SET-01）
              ├─ プロフィール（SET-02）
              ├─ 世帯の設定（HH-01）── メンバー（HH-02）── オーナー権限の移譲（HH-03）
              │                      ├─ 招待の作成（INV-01）── 招待の共有（INV-02）
              │                      ├─ 招待の一覧（INV-03）
              │                      └─ 置き場所（LOC-01）── 置き場所の作成・編集（LOC-02）── 選択肢のシート（窓の向きなど）
              ├─ 通知設定（SET-03）
              └─ アカウントの削除（SET-04）

どこからでも：
  世帯の切り替え（HH-10）… ヘッダーから開くシート
  招待リンク https://<招待用ドメイン>/i/{token} ──> 参加の確認（INV-12）
  リマインダー通知のタップ ──> 対象の世帯の今日（TODAY-01）
  完了通知のタップ ──> 対象の植物の詳細（PLANT-10）
```

**タブは「今日」「植物」「設定」の3つ**（2026-11-19 に決定）。設定は、ヘッダーのボタンではなくタブバーから開く。世帯の設定（HH-01）・メンバー・招待は、設定のタブの中で進む（戻るボタンに「設定」と出る）。今日・植物のヘッダーの左には世帯名（HH-10 の入口）だけを置き、iOS 26 のヘッダーのボタンのガラスの背景は付けない。
**置き場所の管理は、世帯の設定（HH-01）に置く**（2026-11-20 に決定）。置き場所は世帯みんなで使う土台の設定で、一度作ればほとんど変えないため、毎日見る植物の一覧（PLANT-01）には管理の入口を置かない。植物の一覧では、置き場所は絞り込みにだけ使う。植物の登録（PLANT-02）では、その場で新しい置き場所を作れるようにする（設定まで行かなくてよいように）。

## 4. 画面ごとの詳細

### 4.1 認証・初回

#### BOOT-01 起動
- Firebase のサインイン状態を確かめる間だけ表示する。
- サインイン済みなら、前回選んでいた世帯の「今日」へ進む（要件1-4）。選択中の世帯は端末に保存されている。
- 世帯から外されていた場合（前回の世帯が一覧にない場合）は、ほかの世帯へ切り替える。1つもなければ ONB-01 へ。

#### AUTH-01 サインイン
- 要素：アプリ名・ひとこと説明、**「Apple でサインイン」**、**「Google でサインイン」**、利用規約とプライバシーポリシーへのリンク【未決：仕様外だがストア審査で必要】
- 挙動：
  - Apple のボタンは Apple のガイドライン（ボタンの形・文言・色）に従う。Google のボタンと同じ大きさ・同じ目立ち方にする（App Store の審査のルール）
  - 押したあと、OS のサインイン画面が出る。戻ってくるまでボタンを読み込み中にする
  - 利用者がキャンセルした場合は、何も表示せずに元に戻す。通信エラーなどはメッセージを出す
- 招待リンクから来た場合（要件3-4）：「招待を受けるには、サインインしてください」のような説明を添える。サインインのあとは INV-12 へ進む

#### AUTH-02 表示名の設定（初回）
- 要素：説明（「家族に表示される名前です」）、入力欄（初期値は Google の名前。Apple は空のことがある）、決定ボタン
- 入力のルール：前後の空白を除いて **1〜30文字**（`docs/decisions/0005`）。空なら「名前を入力してください」、長すぎれば「30文字以内で入力してください」
- あとから SET-02 で変更できる

#### ONB-01 はじめての選択
- どの世帯にも属していないときに出す（要件2-2）。
- 要素：「世帯を作成する」「招待から参加する」の2つの大きな選択肢。「世帯とは」の短い説明（例：自分の家、実家など、植物と家族をまとめる単位）
- 「招待から参加する」は、INV-10（コードの入力）と INV-11（QRの読み取り）を選べるようにする。招待リンクを受け取っている人には「メッセージで届いたリンクを開いてください」と案内する

#### ONB-02 世帯の作成
- 要素：世帯名（必須、例：「自宅」「実家」）、作成ボタン
- 地域（都道府県・市区町村）は任意の項目として、作成時にも聞く（空のまま作成できる。2026-11-17 に決定）。入力の方法は HH-01 と同じ
- 作成したユーザーがオーナーになる（要件2-1）。作成後は「今日」へ（植物がまだないので、空の状態を出す）

### 4.2 今日やること

#### TODAY-01 今日やること（ホーム）
- 表示の対象：選択中の世帯で、予定日が今日以前の、未完了のタスク（要件9-1）。アーカイブした植物と、一時停止中のタスクは出さない。
- ヘッダー：世帯名（タップで HH-10）、日付、表示の切り替え
- **タスクの項目（TaskCard）** に出すもの（要件9-2）
  - 植物名、置き場所（未設定のこともある）
  - 作業の種類（アイコン + 名前。「その他」は自由入力の作業名）
  - 予定日
  - 実行条件（設定されていれば。例：「土の表面が乾いていたら」）
  - **期限切れ**：予定日を過ぎていれば、区別した見た目と「3日過ぎています」（要件9-3）
  - **今日は不要**：「やらない方がよい」提案があれば、「今日は不要」の表示と理由を添え、通常のタスクと区別する（要件9-4）。MVP では植え替え以外のプロバイダがないので出番は少ないが、フェーズ2（天気）で増える
  - **条件つきの提案**：条件と、その条件にあてはまる場合の行動をあわせて示す。判断はユーザーに任せる見せ方にする（要件19-4）
  - タスクのメモ（例：「底から流れるまでたっぷり」）を出すかは【未決】（出すなら折りたたみ）
- 項目の操作（編集者以上）
  - **完了**（ワンタップ、もっとも押しやすい位置）
  - スキップ（TODAY-03）
  - 実施日を変えて記録（TODAY-04）
  - 植物の詳細へ（項目のタップ）
  - 完了以外の操作をどこに置くか（スワイプ、「…」メニュー、長押し）は【未決】
- 表示の切り替え（要件9-5）
  - 予定日順（初期値の案）
  - 置き場所ごと（セクションの見出しが置き場所名。未設定は「置き場所未設定」）
  - 作業の種類ごと（水やり・肥料…）
- 状態
  - 読み込み中（スケルトン）
  - **今日の作業がない**：「今日のお手入れはありません」と、直近の次の予定（例：「次はモンステラの水やり（11月3日）」）を出す（要件9-6）
  - **植物が1つもない**：植物の登録へ誘導する
  - 閲覧者：完了・スキップのボタンを出さない
  - 通信エラー：再読み込みを促す
- **17.1 で決めたこと（2026-11-23）**
  - 表示の切り替えは、ヘッダーの右の OS のメニュー（並べ替えのシンボル）に置く（ユーザーが選んだ。毎日開く画面なので、たまにしか変えない操作を一覧の上に出さない）。選んだ表示にチェックを付け、端末に保存して次の起動でも使う
    - 予定日順：API の順（予定日の古い順）のまま、見出しなしで並べる
    - 置き場所ごと：見出しは置き場所名。置き場所名の順に並べ、「置き場所未設定」は最後
    - 作業の種類ごと：見出しは作業の種類の名前。水やり・肥料・植え替え・剪定・その他の順
  - TaskCard：1行目に植物名（`headline`）と、期限切れなら OverdueBadge「3日過ぎています」。2行目に作業の種類（アイコン＋名前）・置き場所・予定日（今日なら「今日」）。その下に実行条件
    - 今日は不要：カードの地を `bg/subtle` にして通常のタスクと区別し、上に「今日は不要」（`suggestion/avoid` の色）と理由を出す。並び順は変えない
    - 条件つき：上に「条件つき」（`suggestion/conditional` の色）と、「もし〜なら、〜」の文を出す
  - タスクのメモは出さない（植物の詳細で見られる。今日の一覧は短く保つ）
  - 完了・スキップなどの操作は 17.2 で足す。17.1 では、カードを押すと植物の詳細（PLANT-10）へ進む
  - 読み込み中は、ほかの画面と同じく OS のくるくる（スケルトンは見送り）。下に引っぱると取り直す（OS の更新の操作）
  - 空の状態（EmptyState）：
    - 植物が1つもない：「植物を登録しましょう」と、植物の登録へのボタン（編集者以上）
    - 今日の作業がない：「今日のお手入れはありません」と、直近の次の予定（「次は ポトス の水やり（11月25日(水)）」）。次の予定もなければ、植物の詳細で周期を決めると出ることを説明する
- リアルタイム：ほかのメンバーが完了・スキップした項目は一覧から外し、「たろうさんが水やりしました」のように **誰が対応したか** を示す（要件9-7）。外れ方（フェードなど）と、名前の出し方（項目の位置に一瞬残す、トーストで出す）は【未決】

#### TODAY-02 完了の取り消し（スナックバー）
- 完了を押した直後に、項目を一覧から外し、画面の下に「水やりを記録しました　**取り消す**」を **5秒間** 出す（設計の楽観的更新）。
- 取り消すと、項目が一覧に戻る（要件10-4）。
- 連続して完了した場合のスナックバーの重なり方は【未決】（最後の1件だけ出す、件数をまとめる、など）
- サーバー側では、記録した本人が10分以内なら取り消せる。スナックバーが消えたあとの取り消しを履歴（PLANT-11）から出すかは【未決】

#### TODAY-03 スキップ（ボトムシート）
- 要素
  - 理由（任意、1つ選ぶ）：「土がまだ湿っている」「天気が悪い」「株が弱っている」「その他」（要件10-7）
  - 「その他」を選んだときだけ、自由入力の欄（200文字まで）
  - 次回の確認日：初期値は **明日**。明日以降の日付に変えられる（要件10-8）
  - 「スキップする」ボタン
- スキップは「作業をしたことにはしない」。タスクは確認日にまた一覧に出る。
- スキップでは完了通知を送らない（要件16-7）。

#### TODAY-04 実施日を変えて記録（ボトムシート）
- 「昨日やったのを記録し忘れた」ためのもの（要件10-3）。
- 要素：実施日の選択（初期値は今日。**未来の日は選べない**）、「記録する」ボタン
- 次回の予定は、選んだ日を起点に計算される。

#### TODAY-05 すでに完了されている（ダイアログ）
- 同じ回をほかのメンバーが先に完了していた場合に出す（要件11-2）。楽観的に消した項目は元に戻す。
- 要素：「たろうさんが 10:15 に水やりを記録しています」、**「記録しない」**（初期の選択）、**「追加で記録する」**（要件11-3）
- 例：家族が水やりをしたのに気づかず、自分も水をあげてしまった場合に、事実として記録を残せる。

#### TODAY-06 まとめて完了（選択モード）
- 複数のタスクを選んで、まとめて完了する（要件10-9）。
- 要素：選択モードへの入り方【未決】、項目ごとのチェック、「すべて選択」、下部に「3件を完了」ボタン
- 結果はタスクごとに返る（成功・すでに完了・エラー）。一部だけ失敗したときの見せ方（失敗した項目を残して理由を出す）をデザインしておく。

### 4.3 植物

#### PLANT-01 植物の一覧
- 要素（要件5-4）：植物ごとに、名前、置き場所（未設定なら「置き場所未設定」）、**次のお手入れの予定日**。どの作業かは、API に作業の種類が足されてから出す（バックエンドに依頼中。それまでは「次の予定 11月26日(木)」と日付だけ。予定のタスクがなければ「予定なし」。2026-11-20 に決定）
- 検索：名前での検索（要件5-5）。OS のヘッダーの検索バーを使う。入力が止まってから API の `q` で探す（ひらがな・カタカナなどを区別しない探し方は API に任せる）
- 絞り込み：置き場所（「すべて」「リビングの南窓」…「置き場所未設定」）。検索バーの下に、横に流れる絞り込みのチップ（FilterChips）を置く。置き場所が1つもなければ出さない。絞り込みはアプリの中で行う（API には「置き場所未設定」の条件がないため）
- 並び順：**次の予定日が近い順**。予定のタスクがない植物は最後に、名前順で並べる（2026-11-20 に決定。一覧は植物のダッシュボードなので、お世話が近いものを上に）
- 追加ボタン（編集者以上）：ヘッダーの右に「追加」（背景なし）。16.2b で付ける
- 入口：アーカイブした植物（PLANT-05）は、一覧の**いちばん下**の行（「アーカイブした植物　3」）。アーカイブした植物があり、検索・絞り込みをしていないときだけ出す。たまにしか使わないので、ヘッダーには置かない（2026-11-21 に決定）。「近くの園芸店を探す」【未決：配置】。置き場所の管理（LOC-01）は世帯の設定に置き、ここには置かない（2026-11-20 に決定）
- 状態：植物が0件（登録への誘導）、検索・絞り込みの結果が0件（条件を変えるよう促す）、読み込み中、エラー
- 株数に上限はない（要件5-3）。200株でも使える一覧にする（設計の性能の目標）

#### PLANT-02 植物の登録・編集
- 入力の項目（要件5-2）

| 項目 | 必須 | 入力の方法 |
|---|---|---|
| 名前 | 必須 | 文字の入力（例：「リビングのモンステラ」）。40文字まで（API の決まり） |
| 種類 | 任意 | 植物マスタから選ぶ（PLANT-03）か、自由入力（50文字まで） |
| 置き場所 | 任意 | 既存の置き場所から選ぶ（ChoiceSheet）。選択肢の最後の「＋ 新しい置き場所」で置き場所の追加（LOC-02）を開き、作ったものをそのまま選ぶ（2026-11-20 に決定） |
| 購入日・お迎え日 | 任意 | OS の日付の選択（DatePicker）。未来の日は選べない（2026-11-20 に決定。植え替えの提案の起点になるため）。「未設定」に戻せる |

- 登録・編集はモーダル。登録は植物の一覧のヘッダーの右の「追加」（編集者以上、背景なし）から、編集は植物の詳細（PLANT-10）のヘッダーの右の「編集」（編集者以上）から開く。保存したらトーストで知らせて閉じる（2026-11-20）
- 編集のときは、下に **アーカイブ**（「枯れた・手放した」）と **削除** を置く（ListRow）。どちらも OS の確認のアラートで確かめ、済んだらトーストで知らせて、詳細ごと閉じて元の一覧（通常の一覧、またはアーカイブした植物）へ戻る（2026-11-21）
  - 削除：「タスク・記録・メモもすべて削除されます」と示して確認する（要件5-7）。取り消せない操作として、赤い見た目で区別する。確認のボタンは「削除する」。アーカイブした植物も削除できる
  - アーカイブ：一覧とリマインダーから外れるが、記録とメモは残ることを説明する（要件5-8）。確認のボタンは「アーカイブする」。アーカイブ中の植物には出さない（解除は詳細から）
- 登録したあと、購入日があり植え替えタスクがなければ、植え替えの提案（PLANT-04）を出す（要件17-1）。

#### PLANT-03 種類の検索
- 種類の欄から開く OS のシート。上に OS の検索バー（開いたら入力できる状態にする）。何も入れていないときは、和名の順の候補を出す
- 和名・学名・別名で検索し、候補を出す（要件6-2）。例：「ポトス」「Epipremnum」
- 候補の項目：和名、学名（小さく）、別名
- 見つからないときは「『〇〇』を種類として入力する」で自由入力に切り替えられる（要件6-3）
- 種類を選ぶと、あとでタスクを作るときに推奨の周期と実行条件が初期値として入る（要件6-4）

#### PLANT-04 植え替えの提案
- 購入日つきで植物を登録したあとに出す（要件17-1）。登録のモーダルを、このモーダルに置き換える。提案がなければ（植え替えのタスクがすでにあるなど）出さずに閉じる（2026-11-20）
- 提案は SuggestionCard（種類の名前「おすすめ」＋本文＋理由＋ボタン）で出す。理由は API の材料（慣らし期間・避けた時期・種類）からアプリが組み立てる（docs/decisions/0028）
- 「日付を変えて入れる」を押すと、カードの中に日付の欄（DateField。提案日が初期値）と「この日で予定に入れる」が出る
- 答えずに閉じた場合は、提案が未回答のまま残る（API の提案の一覧に出る）
- 要素
  - 見出し：「植え替えにおすすめの日」
  - 提案日（例：2027年4月1日）
  - 理由（例：「慣らし期間のあと、真夏を避けた最初の適期です」）（要件17-7）
  - **「この日で予定に入れる」**（採用、要件17-4）
  - **「日付を変えて入れる」**（日付を選んで採用、要件17-5）
  - **「今はしない」**（見送り、要件17-6）。見送った提案は同じ植物に二度と出ない
- 提案を後から見返す場所（植物の詳細に提案カードを残す、など）は【未決】（植物の詳細を作るときに決める）。API には世帯の有効な提案の一覧がある。

#### PLANT-05 アーカイブした植物
- アーカイブした植物の一覧（PlantListItem のアーカイブ済み。右に「11月21日(土)にアーカイブ」）。アーカイブの新しい順。開くと詳細を見られる（記録とメモは閲覧できる）。
- 植物のタブの中の画面（タブバーを出したまま）。一覧の上に「枯れた・手放した植物です」の説明。0件なら「アーカイブした植物はありません」
- 「アーカイブを解除」（編集者以上）は、詳細の「アーカイブ済み」の表示の中に置く（一覧の項目は押すと詳細を開くので、項目に操作を置かない。2026-11-21）。押したら OS の確認のアラート（「植物の一覧とお手入れの通知に戻ります」、決定のボタンは「解除する」）で確かめ、解除したらトーストで知らせて、植物の一覧（PLANT-01）へ戻る（2026-11-22 にユーザーの確認で変更。はじめは詳細にとどまる形だった）

#### PLANT-10 植物の詳細
- ヘッダー：植物名、種類、置き場所、購入日。編集ボタン（編集者以上）
- **お手入れタスクの一覧**（要件8-2）
  - 項目：作業の種類（アイコン）、周期（例：「7日ごと」。季節ごとの周期なら「今：夏 4日ごと」）、次の予定日、実行条件、一時停止中かどうか
  - 項目は TaskListItem（16.3a）。左に作業の種類のアイコン、題名に作業の名前（「その他」は作業名）、補足に周期・次の予定日、その下に実行条件。一時停止中はバッジを出し、次の予定日を出さない
  - 一覧の最後に「＋ お手入れを追加」（編集者以上。アーカイブ中の植物には出さない）。タスクがなければ、周期を決めると「今日」に出ることを説明する
- 履歴・メモ・カレンダーへの入口
- **詳細の構成**：植物名の下に OS のセグメントの切り替え（概要・履歴・メモ・カレンダー）を置き、詳細の中をタブに分ける（2026-11-22 に決定）。概要に、植物の情報（種類・置き場所・購入日）とお手入れタスクの一覧を置く。履歴・メモ・カレンダーは 17.3 で作る（それまでは「準備中」）
- アーカイブ中の植物：「アーカイブ済み」の表示（アーカイブした日と、一覧・通知に出ないこと）を出し、タスクの操作を出さない。編集者以上には、表示の中に「アーカイブを解除」（枠つきのボタン）を出す。編集の入口は残す（削除のため）（16.2d）
- リアルタイム：表示中にほかのメンバーが植物を削除した場合、「この植物は削除されました」と示して一覧へ戻る（`not_found` と同じ扱い）

#### PLANT-11 履歴
- 記録を新しい順に（要件12-1）。項目：日時、作業の種類、**完了かスキップか**（スキップなら理由）、対応したメンバー名
- 作業の種類で絞り込める（要件12-2）
- 上部に、作業の種類ごとの **最終実施日** （例：水やり 10月29日、肥料 9月15日）を出す（要件12-3）
- 世帯から外れたメンバーや退会したユーザーの記録も、名前を残して表示する（要件12-5）。退会したユーザーは「退会したユーザー」と表示する
- 「追加で記録」した記録の見せ方【未決】
- 編集者以上：項目から記録の編集・削除（PLANT-12）
- 件数が多いので、下へスクロールすると続きを読み込む

#### PLANT-12 記録の編集・削除
- 実施日の変更と、記録の削除（要件12-4）。
- 最新の完了記録を変えると次回の予定日が計算し直されることを、ひとこと示すとよい。

#### PLANT-13 メモの一覧
- メモを新しい順に。項目：本文、作成日時、作成者、編集済みなら「編集済み」（要件13-2、13-3）
- 編集・削除は、**メモを書いた本人とオーナーだけ**（要件13-3）。ほかの編集者には出さない
- 空の状態：「植物の様子や気づいたことを残しましょう」など

#### PLANT-14 メモの作成・編集
- 複数行の入力欄、文字数の表示（**1〜2000文字**）、保存ボタン
- 空、または2000文字を超える場合は保存できず、修正を促す（要件13-4）
- 画像の添付はない（要件13-5）

#### PLANT-15 カレンダー
- 月単位のカレンダー（`react-native-calendars`）に、その植物の
  - 過去の記録：**完了** と **スキップ**
  - 今後の **予定日**
  - **メモを書いた日**
  を表示する（要件14-1、14-3）
- 作業の種類（5種類）×状態（完了・スキップ・予定）の区別をアイコンや色で表す（要件14-2）。1日に複数の作業が重なる場合の表し方（点を並べる、など）も決める
- 前月・翌月へ移動できる（要件14-5）
- 凡例を用意する

#### PLANT-16 日付の詳細
- カレンダーの日付を選ぶと、その日の記録（対応したメンバーを含む）、予定、メモの一覧を出す（要件14-4）。

### 4.4 お手入れタスク

#### TASK-01 お手入れタスクの作成・編集
- 入力の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| 作業の種類 | 必須 | 水やり・肥料・植え替え・剪定・その他（要件8-1）。OS のセグメントの切り替えで選び、選んだ種類をアイコンと名前でも示す。作成のあとは変えられない（API の決まり） |
| 作業名 | 「その他」のときだけ必須 | 自由入力（例：「葉水」「葉の拭き掃除」）（要件8-3）。20文字まで |
| 周期 | 必須 | 数（1以上）＋単位（日・週・か月）（要件8-1）。IntervalInput（数字の入力欄＋OS のセグメントの切り替え＋「ごと」）。日は365、週は52、か月は24まで |
| 季節ごとの周期 | 任意 | 春・夏・秋・冬で別の周期（要件8-6）。例：水やり 夏4日・冬14日。オンにすると、周期の欄の代わりに4つの季節の周期を入れる |
| 初回の予定日 | 必須 | 日付の選択（要件8-4）。初期値は今日で、今日より前は選べない（作った直後から期限切れにならないように。2026-11-22） |
| 実行条件 | 任意 | 例：「土の表面が乾いていたら」「葉が垂れていたら」（要件8-5）。100文字まで。よく使う条件の候補は MVP では出さない（植物マスタのおすすめだけを初期値に入れる。2026-11-22） |
| メモ | 任意 | 例：「底から流れるまでたっぷり」（要件8-4）。200文字まで |

- 植物マスタと紐づく植物なら、推奨の周期と実行条件が **初期値として入る**。「おすすめの値です」と分かるようにする（要件6-4）
  - いまの API（task-defaults）が返すのは、出典で確かめた水やりの実行条件だけ（推奨の周期はまだない）。実行条件の下に「植物の種類に合わせたおすすめです」と出す（おすすめのままのときだけ）
  - 作業の種類を変えると、実行条件と周期は、空かおすすめ・目安のままなら新しい種類のものに入れ替え、自分で書いた値は残す
  - 植え替えは周期の目安に24か月を入れる（提案の採用で作るタスクと同じ。docs/decisions/0028）。ほかの種類は、出典のある目安がないので空にする
- 季節ごとの周期の入力は、ふだんは閉じておき、OS のスイッチ「季節ごとに変える」で開く（SeasonalIntervalEditor。2026-11-22）。開くと、春（3〜5月）・夏・秋・冬の周期の入力が出て、それまでの周期で埋めておく
  - 開いているあいだは、基本の「周期」の欄を隠す（2026-11-22。基本の周期と季節の周期を重ねて入れさせない。API は季節のない季節に基本の周期を使うが、4つとも入れるので基本の周期は使われない）。API が必須にしている基本の周期には、春の周期を入れて送る
  - スイッチは周期の欄の上に置き、切り替えてもスイッチの位置が動かないようにする
- 周期の数の欄には、プレースホルダー「例：7」を出す（2026-11-22。何を入れる欄かわかるように。「7」だけだと入力済みの値に見えるので、例と分かる形にする）
- 作成はモーダル。追加したらトーストで知らせて閉じる（16.3a）
- 編集のときの操作（16.3b）
  - 植物の詳細（PLANT-10）のタスクの項目を押すと開くモーダル（`plants/[id]/tasks/[taskId]`）。編集者以上で、アーカイブ中でない植物だけ押せる。タスク1件を取る API はないので、植物のタスクの一覧から探す
  - 周期・季節ごとの周期・作業名（「その他」だけ）・実行条件・メモ・次回の予定日の変更（要件8-8）。作業の種類は変えられないので、アイコンと名前だけを出す
  - 予定日の欄の見出しは「次の予定日」。下に「周期を変えても、次の予定日はそのままです。新しい周期は、次に完了したときから使います」と示す（API の決まり）
  - 予定日は **変えたときだけ送る**（送った予定日は手で決めた日になり、季節が変わっても計算し直さなくなるため。API の決まり）
  - 選べる予定日は、今日と今の予定日の早いほうから（期限切れのタスクも、そのまま保存できるように）
  - 保存したら、トーストで知らせて閉じる
  - フォームの下に、植物の編集（PLANT-02）と同じく行を並べる。押したら、トーストで知らせてモーダルを閉じる（フォームの書きかけは保存しない）
    - **一時停止 / 再開**（要件8-9）。有効なら「一時停止する」（補足：再開するまで、今日やることと通知に出ません）、一時停止中なら「再開する」（補足：次の予定日が過ぎていたら、今日になります）。どちらも元に戻せるので、確認は出さない。再開のトーストに次の予定日を出す
    - **削除**（要件8-10。赤い文字）。「これまでの記録は履歴に残ります」と示して確認する
- **植え替えの予定日を真夏（7〜8月）や真冬（12〜2月）にした場合**、「この時期の植え替えは株を傷めやすい」という注意を出す。保存は止めない（要件17-8）
  - 16.3c：判定はサーバー（docs/decisions/0028）。植え替えのタスクを作成・保存したあとに提案の一覧を取り直し、そのタスクへの `repotting.avoid` の提案があれば、OS のアラートで出す（ユーザーが選んだ。2026-11-22）
    - 題名「植え替えの時期に注意」、本文は「{日付}は植え替えに向かない時期です」＋時期ごとの理由（真夏：暑さで生長が鈍り、回復しにくい／真冬：寒さで根が傷みやすい／種類ごとのルール：この植物の種類では向かない時期）＋「予定日はこのまま保存しました。変えるときは、お手入れを編集してください」
    - 植物の詳細（PLANT-10）のタスクの項目にも、注意の1行を残す。予定日を変えて避ける時期でなくなると、サーバーが助言を撤回するので消える

### 4.5 置き場所

#### LOC-01 置き場所の一覧
- 設定のタブの中の画面（戻るボタンに「世帯の設定」と出る）。世帯の設定（HH-01）の「置き場所」から開く。閲覧者も開ける
- 項目：置き場所名、環境の要約（例：「室内・南・窓際・レースカーテン」。未設定の項目は出さない）、右に植物の数（例：「3株」。アーカイブした植物は数えない）
- 編集者以上：上に「置き場所を追加」のボタン。項目を押すと編集（LOC-02）
- 閲覧者：追加のボタンを出さず、項目も押せない（要約で環境は見られる）
- 状態：0件（「置き場所はまだありません」と、編集者以上には追加の案内）、読み込み中、エラー（再試行）
- 並びは作成の古い順（API の順のまま）

#### LOC-02 置き場所の作成・編集
- 入力の項目（要件7-2）

| 項目 | 必須 | 選択肢 |
|---|---|---|
| 置き場所名 | 必須 | 例：「リビングの南窓」 |
| 室内か屋外か | 任意 | 室内 / 屋外（最初は室内） |
| 窓の向き（屋外では「向き」） | 任意 | 未設定 / 北・北東・東・南東・南・南西・西・北西（8方位。API の WindowDirection） |
| 窓からの距離の目安 | 任意（室内だけ） | 未設定 / 窓際 / 窓から少し離れた所 / 部屋の奥（API の WindowDistance） |
| 遮光 | 任意（室内だけ） | 未設定 / なし / レースカーテンなど（API の Shading） |

- 選択肢は、一覧の項目（今の値を右に出す）を押して開く OS のシート（ChoiceSheet）で選ぶ。都道府県の選択と同じ形（2026-11-20）
- 屋外にしたときは、窓からの距離と遮光の欄を隠し、保存のときに未設定に戻す（屋外では意味がないため）
- アプリが知らない値（API にあとから足された値）は「未設定」と出す
- 作成・編集はモーダル。保存したら閉じ、トースト（Toast）で「保存しました」と知らせる。キーボードは送ったときに閉じる

- 環境の項目は MVP の画面ではまだ助言に使わない（フェーズ2の天気の助言で使う）。入力を任意にし、負担に見えないようにする。
- 削除：編集の画面の下の「この置き場所を削除」から。紐づく植物の数を示して確認し（例：「3株の植物は「置き場所未設定」になります」。0株なら数を出さない）、それらの植物は「置き場所未設定」になる（要件7-4）。確認のボタンは「削除する」

### 4.6 世帯・メンバー・招待

#### HH-10 世帯の切り替え（ボトムシート）
- 所属する世帯の一覧。項目：世帯名、自分のロール、選択中の印
- 下に「世帯を作成する」「招待から参加する」
- 切り替えると、今日・植物の一覧が、その世帯の内容になる（要件2-4）。選択中の世帯は端末に保存する。
- 世帯が1つだけのときも、切り替えの入口（ヘッダーの世帯名）を出す。シートの「世帯を作成する」「招待から参加する」が、2つ目の世帯の入口になるため（2026-11-17 に決定）

#### HH-01 世帯の設定
- 世帯名の変更（オーナーだけ、要件2-5）。保存したら、トースト（Toast）で「保存しました」と知らせ、キーボードを閉じる（2026-11-19）
- 地域（都道府県・市区町村、任意、要件7-5）。都道府県は47の一覧から選び（「未設定」も選べる）、市区町村は文字で入力する（50文字まで。2026-11-17 に決定）
- メンバー（HH-02）、招待（INV-01 / INV-03。オーナーだけ）、置き場所（LOC-01。全員）への入口
- **退出**（オーナー以外、要件2-7）：「退出すると、この世帯の植物を見られなくなります」と確認する
- 唯一のオーナーが退出しようとして、ほかにメンバーがいる場合：退出させず、先にオーナー権限を移すよう案内する（要件2-8）
- **世帯の削除**（オーナーだけ、要件2-6）：「植物・タスク・記録・メモがすべて消えます」と示して確認する。確認は OS の確認のアラート（赤い「削除」のボタン）で行い、世帯名の入力は求めない（2026-11-17 に決定）

#### HH-02 メンバーの一覧
- 項目：表示名、ロール（バッジ）、自分かどうか
- オーナーの操作（要件4-2）：ロールの変更（編集者 ⇄ 閲覧者）、メンバーの削除、オーナー権限の移譲
- メンバーを削除するとき：「このメンバーの過去の記録は名前つきで残ります」と示す（要件4-7）
- ロールの説明（オーナー・編集者・閲覧者で何ができるか）を見られるとよい

#### HH-03 オーナー権限の移譲
- 移す先のメンバーを選んで確認する。「移すと、あなたは編集者になります」と示す（要件4-8）。
- 退出（要件2-8）やアカウントの削除（要件1-7）の途中からも来る。

#### INV-01 招待の作成
- 付与するロールを選ぶ：**編集者**（記録・編集ができる）/ **閲覧者**（見るだけ）。ロールの違いを説明する（要件3-1）
- 有効期限は7日で固定し、選ばせない（仕様と API のとおり。2026-11-19 に決定）
- HH-01 の「招待」（INV-03）の「招待する」から、モーダルで開く。作ったら、同じモーダルのまま INV-02 に切り替える（招待リンクの URL は作成のときにしか受け取れないため。2026-11-19）

#### INV-02 招待の共有
- 1つの招待に、次の3つがある（要件3-1、3-2）
  - **招待リンク**：「共有する」で OS の共有シートを開く（LINE、メッセージなど）
  - **QRコード**：その場で相手に読み取ってもらう
  - **招待コード**（8文字）：電話などで口頭で伝えるとき、アプリを入れたばかりの人が入力するとき
- 有効期限と付与するロールを表示する。1つの招待は、期限内なら何人でも使える

#### INV-03 招待の一覧
- 有効な招待の一覧：招待コード、ロール、有効期限（新しい順）。作成者は出さない（招待を作れるのはオーナーだけで、API も返さないため。2026-11-19）
- 招待リンクと QR は一覧からは出せない（URL は作成のときにしか受け取れない）。コードは一覧に出るので、口頭で伝え直せる
- **取り消し**（確認つき、要件3-7）。項目の右の「取り消す」のボタン（枠つき）を押すと、OS の確認のアラートで取り消す（2026-11-19）。取り消すと、そのリンク・QR・コードはすぐに使えなくなる

#### INV-10 招待コードの入力
- 8文字の入力欄（紛らわしい文字は使わない仕様。大文字・小文字を区別しない入力にするとよい）。決定で INV-12 へ。
- 入力は大文字にそろえ、空白・ハイフンを除き、全角を半角にしてから確かめる（口頭で伝えたときの揺れを吸収する）
- ONB-01 と HH-10 の「招待から参加する」で開く。この画面に「QRコードを読み取る」（INV-11）の入口も置く（2026-11-19）

#### INV-11 QRコードの読み取り
- カメラの許可を求める（拒否されたときに、端末の設定を開く導線を出す）。
- 読み取ったら INV-12 へ。招待ではない QR を読んだ場合のメッセージも用意する。
- 招待用ドメインが決まるまでは（タスク 15.3）、ドメインは問わず、`/i/<トークン>` の形のリンクを招待とみなす

#### INV-12 参加の確認
- 世帯名と、付与されるロールを示し、「参加する」で確認する（要件3-3）
- 状態
  - 読み込み中
  - **有効**：世帯名・ロール・「参加する」
  - **無効**（期限切れ・取り消し済み）：「この招待は無効です。招待した人に新しい招待をお願いしてください」（要件3-5）
  - **すでに参加している**：「すでにこの世帯に参加しています」と、その世帯を開くボタン（要件3-6）
    - 【バックエンドに依頼中】招待の内容に世帯の ID がなく、その世帯に切り替えられない。返ってくるまでは「今日」を開くボタンにする（2026-11-19）
- 参加すると、その世帯に切り替えて「今日」へ。オーナーには参加の通知が届く（要件3-8）

#### WEB-01 招待のページ（アプリ未インストール時）
- 招待用ドメイン・Universal Links / App Links の検証ファイルと合わせて、タスク 15.3 で作る（15.2 はアプリ側だけ。2026-11-19 に決定）
- アプリが入っていない人が招待リンクを開いたときに、ブラウザで表示する Web ページ（Firebase Hosting）。
- 要素：「〇〇さんから uchinokusa への招待です」のような説明【未決：表示できる情報の範囲】、App Store / Google Play へのリンク、**招待コード（8文字）**、「アプリを入れたら、このコードを入力してください」という案内
- アプリのインストール後に自動で招待画面へ進む仕組み（遅延ディープリンク）は MVP の対象外のため、コードを手で入力してもらう。

## 6. 横断的な挙動

### 6.1 ロールによる表示の切り替え（要件4-5、4-6）
- 選択中の世帯での自分のロールで、ボタンの有無が決まる。

| 操作 | オーナー | 編集者 | 閲覧者 |
|---|---|---|---|
| 今日・植物・履歴・メモ・カレンダーを見る | ○ | ○ | ○ |
| 完了・スキップ・取り消し・まとめて完了 | ○ | ○ | × |
| 植物・置き場所・タスクの作成・編集・削除 | ○ | ○ | × |
| 記録の編集・削除 | ○ | ○ | × |
| メモを書く | ○ | ○ | × |
| メモの編集・削除 | ○（全員の分） | 自分の分だけ | × |
| 提案の採用・見送り | ○ | ○ | × |
| 自分の通知設定 | ○ | ○ | ○ |
| 世帯名・地域の変更、招待、メンバーの管理、移譲、世帯の削除 | ○ | × | × |
| 世帯からの退出 | ほかにオーナーがいれば○ | ○ | ○ |

- **表示中にロールが変わったら、すぐにボタンの有無を更新する**（WebSocket の `role_changed`）。たとえば編集中のフォームを開いている途中で閲覧者になった場合の扱い（閉じて知らせる、など）を決めておく【未決】。
- **世帯から外されたら**（`membership_revoked`）：「〇〇の世帯から外れました」と知らせ、ほかの世帯へ切り替える。世帯がなくなれば ONB-01 へ。

### 6.2 楽観的更新と失敗時の巻き戻し（要件20-5、11-6）
1. 完了を押す → すぐに一覧から消し、スナックバーを出す
2. サーバーが成功 → そのまま
3. サーバーが「すでに完了」 → 項目を戻し、TODAY-05 を出す
4. 通信できない → 項目を戻し、「記録できませんでした。通信が戻ったら、もう一度お試しください」
5. サーバーの障害 → 項目を戻し、再試行を案内する

### 6.3 リアルタイム同期（要件11）
- ほかのメンバーの変更は、数秒以内に画面に反映される。デザインでは「**表示している内容が、自分が触っていないのに変わる**」ことを前提にする。
  - 今日の一覧から項目が消える（誰が対応したかを示す）
  - 植物やメモが増える・変わる・消える
  - 開いている植物や世帯が削除される → 知らせて一覧へ戻る
- アプリがバックグラウンドから戻ったとき、通信が回復したときは、データを取り直す（要件11-5）。そのときの更新中の表示（控えめに）を決める。

### 6.4 エラーの見せ方（設計の「エラー処理」）

| 種類 | 画面での見せ方 |
|---|---|
| 入力の誤り | 入力欄の下に理由（例：「30文字以内で入力してください」） |
| 未認証（トークンの期限切れなど） | 裏で更新して再試行。だめならサインイン画面へ |
| 権限なし | 「この操作には編集権限が必要です」 |
| 見つからない | 一覧へ戻る（削除された、または世帯から外れた） |
| 状態の衝突 | 何が起きたか（誰がいつ完了したか、など）を示し、最新の内容を取り直す |
| 招待が無効 | INV-12 の無効の状態 |
| サーバーの障害 | 「時間をおいてもう一度お試しください」と再試行のボタン |

### 6.5 ディープリンクと通知からの遷移
- 招待リンク `https://<招待用ドメイン>/i/{token}`
  - サインイン済み → INV-12
  - 未サインイン → AUTH-01（招待の説明つき） → AUTH-02（初回のみ） → INV-12（要件3-4）
- リマインダー通知 → 通知の世帯に切り替えて TODAY-01（要件15-5）
- 完了通知 → 植物の詳細 PLANT-10（要件16-5）

### 6.6 日付とタイムゾーン
- 「今日」は端末の日付で決まる（要件15-7）。日付をまたいだときに「今日」の内容を取り直す。
- 日付の表示形式（「11月3日（月）」「明日」「3日後」など相対表現を使うか）は【未決】

## 7. 通知の文言（デザインと一緒に決めるもの）

| 通知 | 内容の要件 | 文言の例 |

## 8. 列挙値と表示名

| 値 | 表示名（案） |

## 10. 未決事項（デザインで決めること・仕様で決まっていないこと）

### 画面の構成
1. **タブの構成**：「今日」「植物」の2つか、「設定（世帯）」を加えた3つか
2. **世帯の切り替えの位置**：ヘッダーの世帯名をタップ、が第一案。世帯が1つのときの見せ方
3. **植物の詳細の構成**：縦に並べるか、詳細内のタブ（概要・履歴・メモ・カレンダー）に分けるか
4. ~~**置き場所の管理の入口**~~：世帯の設定（HH-01）に決定（2026-11-20）。植物の一覧では絞り込みだけ

6. **提案を後から見返す場所**：植物の登録の直後以外に、提案をどこに出すか

### 操作
7. **完了以外の操作（スキップ・実施日の変更）の置き方**：スワイプ、「…」メニュー、長押し
8. **まとめて完了の入り方**：「選択」ボタン、長押し
9. **取り消しの期間**：画面は5秒、サーバーは10分まで受け付ける。スナックバーが消えたあとに履歴からも取り消せるようにするか
10. **ほかのメンバーが対応したときの見せ方**：項目をすぐ消すか、名前を添えて一瞬残すか
11. **編集中にロールが閲覧者に変わった場合**の扱い
12. **通知の許可を求めるタイミング**（初回の世帯の作成のあと、初めてタスクを作ったあと、など）

### 入力
13. 世帯名・植物名・置き場所名・作業名・実行条件・タスクのメモの **文字数の上限**（サーバーの実装と合わせて決める必要がある）
