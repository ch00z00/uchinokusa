# 積み残しの課題

1st スプリント（MVP のリリース）を優先するため、**リリース後に対応する**課題をここに集める。
直近で重要度の高い課題は、ここに入れずに、そのタスクの中で対応する。

- 追加するとき：見つけた日・きっかけ（タスク番号など）・内容・対応の案を書く
- 対応したら、行を消し、コミットのメッセージに課題の内容を書く

| 見つけた日 | きっかけ | 課題 | 対応の案 |
|---|---|---|---|
| 2026-11-04 | タスク 6.3（docs/decisions/0017） | 植物の購入日・お迎え日に、未来の日付を入れても受け付ける | 世帯のタイムゾーンの「今日」より後の日付を 422（`fields.acquiredOn = invalid`）にする。植え替えの提案（10.2）の起点になるので、提案の結果もあわせて確かめる |
| 2026-11-04 | タスク 6.3（docs/decisions/0017） | 植物の一覧で、「置き場所が未設定の植物」だけを絞り込む条件がない | アプリの一覧で必要になったら、`GET /households/{id}/plants` に条件を追加する |
| 2026-11-04 | タスク 7.1（docs/decisions/0018） | アーカイブした植物にも、お手入れタスクを作れる・変更できる | 植物がアーカイブ済みなら 409（新しいエラーコード `plant_archived`）にする。今日やること・リマインダーではアーカイブした植物を除くので、実害は小さい |
| 2026-11-05 | タスク 8.1（docs/decisions/0020） | 完了の実施日が未来かどうかを、世帯のタイムゾーンで判定している。世帯より時差が進んだ場所（旅行先など）から、その場所の「今日」を送ると 422 になる | アプリが端末のタイムゾーンを送り、許容する日付を1日広げる。困る声が出たら対応する |
| 2026-11-05 | タスク 8.4（docs/decisions/0023） | 完了の記録をすべて消すと、次回予定は消した記録から計算した日のまま残る | 最初の完了を消したら、記録の `prev_next_due_on`（記録する前の予定日）に戻す。困る声が出たら対応する |
| 2026-11-06 | タスク 9.3（docs/decisions/0026） | カレンダーの1か月の記録とメモの件数に上限がない | 実際の使い方でレスポンスが大きくなりすぎるようなら、件数の上限か、日付を選んだときの別の取得を加える |
| 2026-11-06 | タスク 10.2（docs/decisions/0028） | 記録（完了・スキップ・取り消し・記録の編集）で植え替えタスクの予定日が変わっても、避ける時期の助言を評価し直さない。早めに完了すると、前の予定日の助言がその日まで一覧に残る | `CareRecordService` の記録のあとにも `task_due_changed` で評価する |
| 2026-11-06 | タスク 10.2（docs/decisions/0028） | 植物の購入日をあとから入れた・変えたときは、植え替えの提案を作らない | 植物の編集で購入日が変わったら `plant_created` と同じ評価をする（きっかけを足す） |
