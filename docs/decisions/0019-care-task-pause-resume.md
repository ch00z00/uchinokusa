# 0019. タスクを再開したときの次回予定は「今の次回予定と今日の遅いほう」にする

- 状態：採用
- 日付：2026-11-04
- 関連：タスク 7.2、`server/internal/domain/care_task.go`（`ResumedNextDueOn`）、`server/internal/app/care_task.go`、要件8-9
- 前提：0018（初回の予定日は既定で今日、予定日の手動変更と `due_overridden`）

## 決定
1. **一時停止（`POST /tasks/{id}/pause`）では、次回予定を変えない**
   - 状態を `paused` にするだけにする。予定・今日やること・リマインダーの対象から外すのは、それぞれの一覧で `status = 'active'` に絞って行う（植物の一覧の `nextDueOn` は 0017 で対応済み。今日やること 9.1、リマインダー 12.3 でも同じ条件にする）
2. **再開（`POST /tasks/{id}/resume`）では、次回予定を `max(今の次回予定, 世帯のタイムゾーンでの今日)` にする**（設計の状態図「再開日以降で次回予定を計算し直す」）
   - 次回予定がまだ先なら、そのまま使う。短い間だけ止めた場合や、手で決めた予定日を残すため
   - 過ぎていたら今日にする。今日やることに出るので、植物の状態を見て、完了かスキップを選べる（0018 の「初回は今日」と同じ考え方）
   - 「最後に完了した日 + 周期」で計算し直す案もあったが、記録（8.x）に依存し、手で決めた予定日を失うため採らなかった
   - 規則は domain の純粋な関数（`ResumedNextDueOn`）にし、今日の日付はサービスが世帯のタイムゾーンから決めて渡す
3. **再開で決めた予定日には、手で変えた印（`due_overridden`）を立てない**。利用者が日付を選んだわけではないため。印がもともと立っていれば、そのまま残す
4. **同じ操作を2回送っても、エラーにしない**
   - 家族の2人が同時に押すことがあるため、すでに一時停止中のタスクへの一時停止は、今の状態を返す（植物のアーカイブと同じ。0017）
   - 一時停止していないタスクへの再開は、予定日を変えずに今の状態を返す。期限切れの予定日を今日に動かすと、期限切れの表示が消えてしまうため
5. 権限は、タスクの変更と同じく編集者以上（`ActionTaskWrite`）。削除したタスク・ほかの世帯のタスクは 404

## 残る課題
- 一時停止中のタスクを完了・スキップできるかは、タスク 8.1・8.2 で決める
- 一時停止・再開の通知（リアルタイムの配信）は、タスク 11.x で加える
