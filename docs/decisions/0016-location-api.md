# 0016. 置き場所の環境の項目は固定の選択肢にし、削除の確認には一覧の植物の数を使う

- 状態：採用
- 日付：2026-11-04
- 関連：タスク 6.2、`server/internal/domain/location.go`、`server/internal/app/location.go`、`server/db/migrations/00003_location_checks.sql`、要件7-1〜7-4

## 決定
1. **環境の項目は、自由入力ではなく固定の選択肢にする**
   - 窓の向き：8方位（`n`、`ne`、`e`、`se`、`s`、`sw`、`w`、`nw`）。屋外では、その場所が面している向きを表す
   - 窓からの距離：`near`（窓際）、`middle`（窓から少し離れた所）、`far`（部屋の奥）
   - 遮光：`none`（遮光なし）、`sheer`（レースカーテンなどで光を和らげている）
   - フェーズ2の天気の助言で、値を条件に使うため。自由入力の文から判断するのは難しい
   - 距離にはメートルの境目を決めない。出典で確かめた基準がなく、利用者も部屋で測らないため、感覚で選べる言葉にする
   - どの項目も任意で、未設定（NULL）は「わからない」を表す。室内か屋外かは、省くと室内にする（室内観葉植物のアプリのため）
   - 値はアプリの検証（`invalid`）と DB の CHECK 制約の両方で決める（00001 の方針どおり、列は text のまま）
2. **変更の API（PATCH）は、世帯（0011）と同じく、送った項目だけを変え、空文字で未設定に戻す**
   - そのため、リクエストの環境の項目は列挙型ではなく文字列で定義し、値の説明に列挙型を挙げる。レスポンスは列挙型にする
3. **削除の前の確認には、一覧（`GET /households/{id}/locations`）の `plantCount` を使う**
   - 確認のための API を別に作らない。一覧の表示にも数を出せる
   - `plantCount` はアーカイブした植物を除いて数える（植物の一覧に表示される数とそろえる）。削除すると、アーカイブした植物も「置き場所未設定」になる
   - 植物は外部キーの `ON DELETE SET NULL (location_id)` で未設定になる。植物は消えず、世帯にも属したまま
4. **置き場所の ID だけのパス（`/locations/{id}`）では、置き場所から世帯を探してから権限を確かめる**
   - 置き場所がない場合と、所属していない世帯の置き場所の場合は、どちらも 404 にする（存在を明かさない）
   - 変更・削除の SQL にも世帯の条件を入れる（`structure.md` の規約。世帯を探してから変更するまでのあいだに、ほかの世帯の行を触らないことも保証する）

## 残る課題
- 置き場所の変更の通知（`households.version` を増やす・リアルタイムの配信）は、タスク 11.x で加える
- 同じ名前の置き場所は禁止していない。一覧で区別しにくければ、利用者が名前を変えられる
