# 0024. 今日やること一覧は端末の日付で決め、提案は一覧のタスクの分だけまとめて読む

- 状態：採用
- 日付：2026-11-05
- 関連：タスク 9.1、`server/internal/domain/today.go`、`server/internal/app/today.go`、`server/internal/adapter/postgres/today.go`、`server/db/queries/today.sql`、要件9-1〜9-4・9-6
- 前提：設計の TodayQuery、0019、0020

## 決定
1. **`GET /households/{id}/today?date=YYYY-MM-DD` の「今日」は、アプリが送る端末の日付にする**（設計どおり）
   - 省くと、世帯のタイムゾーンでの今日にする（0020 と同じ決め方）
   - 日付の範囲は制限しない。読み出すだけで、データを変えないため
2. **対象は、予定日が今日以前の、有効なタスク（一時停止・削除を除く）で、アーカイブしていない植物のもの**（要件9-1、0019）
   - 予定日の古い順（期限切れが先）に並べ、同じ日は植物名・作業の種類の順にする
   - 置き場所ごと・作業の種類ごとのまとめ表示（要件9-5）は、アプリが並べ替えて行う。サーバーの順番は1つにする
3. **各項目は、タスクそのもの（`CareTask`）と、表示用の植物名・置き場所を持つ**
   - タスクをそのまま返すのは、一覧から完了・スキップするときに `cycleSeq` が要るため（0020）
   - 期限切れの日数は domain で計算する（今日が予定日なら 0）
4. **提案は、一覧に載るタスクの分を、1回のクエリでまとめて読む**（N+1 にしない）
   - 載せるのは、今日の時点で有効な（未回答・有効期間内の）「やらない方がよい」「条件つき」の提案だけ（要件9-4）。「実施をすすめる」提案は、別の一覧（10.x）で扱う
   - 提案を作る仕組みは 10.x で加える。それまでは、`suggestions` はいつも空
   - 提案の本文と理由は、i18n のキーとパラメーターのまま返し、文言はアプリが引く
5. **今日やることがなければ、直近の次の予定を1件だけ返す**（要件9-6）。今日やることがある日は返さない（画面で使わないため）
6. 世帯のタスクの取り出しは、`care_tasks (household_id, status, next_due_on)` のインデックスを使う1回のクエリで行う（設計の性能の目標：植物200株・タスク600件で p95 300ms 以内）

## 残る課題
- 別のメンバーが完了・スキップしたときに、一覧から外す配信（要件9-7）は、タスク 11.x で加える
