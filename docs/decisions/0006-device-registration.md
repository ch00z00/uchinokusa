# 0006. 端末の登録は FCM トークンで上書きし、解除は常に 204 を返す

- 状態：採用
- 日付：2026-10-30
- 関連：タスク 2.2、`server/internal/domain/device.go`、`server/db/queries/user_devices.sql`、要件1-5・15-7

## 決定
1. **登録は `POST /me/devices` の1つで、新規と更新を兼ねる（upsert）**
   - アプリは起動のたびに呼ぶ。端末のタイムゾーン（旅行先など）と `last_seen_at` が最新に保たれる
   - `fcm_token` のユニーク制約に対する `INSERT ... ON CONFLICT DO UPDATE` の1文で行い、同時に届いても端末は1つにまとまる
2. **同じ FCM トークンが別のユーザーで登録されたら、新しいユーザーに付け替える**
   - FCM トークンはアプリのインストールごとのもので、ユーザーごとではない。1台の端末でユーザーを切り替えた場合に、前のユーザー宛ての通知が届かないようにする
   - 付け替えても端末の `id` は変わらないが、解除は `user_id` の条件つきなので、前のユーザーが新しいユーザーの端末を外すことはできない
3. **解除（`DELETE /me/devices/{id}`）は、該当する端末がなくても 204 を返す**
   - サインアウトをエラーで止めないため（付け替え済み・削除済みでもサインアウトはできる）
   - 404 を返さないので、ほかのユーザーの端末の ID が存在するかも明かさない
4. **入力の検証はドメインで行い、すべての誤りをまとめて 422 で返す**
   - `platform` はリクエストでは文字列として受け取る。oapi-codegen は列挙値を検証しないため、ドメインで `ios` / `android` 以外を `invalid` にする
   - `timeZone` は `time.LoadLocation` で読み込めるかで確かめる。`Local`（サーバーのタイムゾーン）は除く
5. **タイムゾーンのデータ（`time/tzdata`）をバイナリに埋め込む**
   - 実行環境のコンテナに tzdata がないと、正しいタイムゾーンも `invalid` になってしまうため。バイナリが約450KB大きくなる

## 補足
- FCM が `UNREGISTERED` を返したトークンの削除は、通知の送信（タスク 12.1）で行う
