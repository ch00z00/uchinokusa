# 0028. 植え替えのプロバイダは登録と予定日の変更で評価し、前の予定日の助言は撤回する

- 状態：採用
- 日付：2026-11-06
- 関連：タスク 10.2、`server/internal/advisor/repotting.go`、`server/internal/app/suggestion.go`・`plant.go`・`care_task.go`、`server/db/queries/suggestions.sql`、要件17-1〜17-9
- 前提：0009（時期のルール）、0027（助言プロバイダの仕組み）

## 決定
1. **植え替えのプロバイダ（`advisor.Repotting`、ID は `repotting.v1`）は、2つのきっかけで評価する**（設計の RepottingAdvisor）
   - **植物の登録**（`plant_created`）：購入日があり、植え替えタスク（削除を除く）がなければ、植え替えタスクを作る提案を出す（要件17-1）
     - 提案日は `RepottingRule.Propose`（購入日 + 14日と今日の遅いほうから、最初の適期）。ルールは、植物マスタに種類ごとの適期があればそれを、なければ既定値を使う（0009）
     - 理由の材料（`reasonParams`）は、慣らし期間を待ったか・慣らし期間の日数・飛ばした避ける時期・種類ごとのルールを使った場合の種類の名前（要件17-7）。文言はアプリが i18n で組み立てる
     - 期限は付けない。提案日を過ぎてから採用する場合は、日付を変えて採用できる
     - 重複防止のキーは `repotting:initial:{植物の ID}`。見送ると、同じ植物には二度と出さない（要件17-6）
   - **タスクの予定日の変更**（`task_due_changed`）：有効な植え替えタスクの予定日が避ける時期なら、やらない方がよいことの助言（`avoid` / `info`）を出す。設定自体は妨げない（要件17-8）
     - 理由のキーは、時期ごとに `repotting.avoid.midsummer.reason`（暑さで生長が鈍り、回復しにくい）・`repotting.avoid.midwinter.reason`（寒さで根が傷みやすい）
     - 有効期間は今日から予定日まで。過ぎた予定日には出さない
     - 重複防止のキーは `repotting:avoid:{タスクの ID}:{予定日}`。予定日ごとに別の助言にし、ある日の助言を見送っても、別の日の助言は出す
2. **植え替えタスクの周期は24か月（`advisor.RepottingInterval`）にする**
   - 提案を採用して作るタスクの周期。一般向けの解説の「およそ2年に1回が目安」「1～2年を目安に」の両方に収まる値にした
   - 根詰まりのサイン（鉢底から根が出る、水が染み込まない、など）があれば、周期にかかわらず植え替える。予定日はユーザーが変えられる
3. **きっかけは、変更が成功したあとに、サービスから呼ぶ**
   - 植物の登録（`PlantService.Create`）。購入日の有無は、プロバイダが見る
   - タスクの作成・予定日の変更・一時停止・再開・削除（`CareTaskService`）。種類の判定はプロバイダが行い、サービスは植え替えを知らない
   - 提案の採用でタスクを作ったとき（`SuggestionService.Accept`）。日付を変えて採用した日が、避ける時期のことがあるため
   - 作った提案は、植物・タスクのレスポンスには入れない。アプリは、提案の一覧を取り直して表示する（APIの形を変えずに済むため）
4. **予定日の変更で評価し直したとき、プロバイダが今回返さなかった、そのタスクへの前の未回答の提案は撤回する**（0027 の仕組みに加える）
   - 予定日を真夏から9月に変えたあとに、真夏についての助言が残らないようにするため。一時停止・削除したタスクには、プロバイダが何も返さないので、助言は撤回される
   - 撤回は状態を `expired` にする（0027 の8で使っていなかった値）。失敗したプロバイダの提案は、今の考えがわからないので撤回しない。保存に失敗した提案も、プロバイダが返したものは撤回しない
   - 撤回した提案と同じキーの提案がまた来たら、新しい内容で未回答に戻す（予定日を真夏に戻したとき）。見送った提案は戻さない（要件17-6）
   - 撤回は「プロバイダ × タスク」の単位で行い、ほかのプロバイダ（フェーズ2の天気など）の提案には触れない

## 出典（植え替えの周期）
- コメリ「観葉植物の管理方法」：https://www.komeri.com/contents/howto/html/03030.html
  - 「こんな時は植え替えが必要です！（およそ2年に1回が目安）」
- ミツモア「観葉植物の植え替え」：https://meetsmore.com/services/houseplants-transplant/media/180190
  - 「1～2年を目安に植え替えるとよいですが」「植物の種類にもよりますが、1～2年で鉢の中が窮屈な状態になり、土も古くなります。」
- いずれも一般向けの解説で、植物園や研究機関の資料ではない。種類ごとの周期の出典が見つかったら、植物マスタに持たせることを検討する

## アプリが用意する i18n のキー
- `repotting.initial`（本文。`plantName`・`date`）、`repotting.initial.reason`（理由。`afterAcclimation`・`acclimationDays`・`avoided`・`species`）
- `repotting.avoid`（本文。`plantName`・`date`）、`repotting.avoid.midsummer.reason`・`repotting.avoid.midwinter.reason`・`repotting.avoid.avoid.reason`

## 残る課題
- 記録（完了・スキップ・取り消し・記録の編集）で植え替えタスクの予定日が変わっても、評価し直さない（`docs/backlog.md`）
- 植物の購入日をあとから入れた・変えたときは、植え替えの提案を作らない（`docs/backlog.md`）
