# 0009. 植え替えの時期は植物の種類ごとのルールにし、既定値は出典にもとづいて 5〜6月・9月を適期にする

- 状態：採用
- 日付：2026-10-31
- 関連：タスク 3.2、`server/internal/domain/repotting.go`、要件6-1・17-3・17-7・17-8・17-10
- 置き換える記録：[0008](0008-repotting-period.md)

## 背景
- 最初の要件の「適期 4〜6月・9月、真夏（7〜8月）と真冬（12〜2月）は避ける」は、出典を確かめずに置いた値だった
- ユーザーから「真夏に植え替えてもよい植物も多いのでは」という指摘を受け、調べ直した
  - 一般向けの解説では、観葉植物の植え替えの適期は **5〜9月**（5月中旬〜9月中旬、気温15℃以上が目安）とされることが多い。3〜4月は地域によって寒さが残る
  - 真夏については「暑さで生長が鈍る植物が多いので、避けた方が無難」という書き方で、強く禁じるものではない
  - ポトスのように、暖房の効いた室内なら冬でも植え替えられるとする種類もある
- つまり、時期は種類によって変わり、一律のルールでは足りない。既定値の「4月は適期」は根拠が弱かった

## 決定
1. **植え替えの時期は `RepottingRule`（適期の月、避ける月）として扱い、植物の種類ごとに持てるようにする**
   - 植物マスタの `recommended_care.repotting`（`suitableMonths`、`avoidMonths`）に入れる。jsonb なのでマイグレーションは不要
   - 種類ごとの値は、出典が見つかった種類にだけ入れる（要件17-10）。ない種類は既定値を使う
2. **既定値は、適期 5〜6月・9月、避ける時期 7〜8月（真夏）・12〜2月（真冬）とする**
   - 4月は「どちらでもない」に移した（提案日にはしないが、予定日にしても警告は出さない）
   - 真夏は、根拠が「無難」程度ではあるが、警告を出すだけで設定は妨げない（要件17-8）ため、避ける時期に残した。7〜8月も適期にしたい種類は、種類ごとのルールで上書きする
3. **避ける時期のラベルは、避ける月の季節から決める**（夏 → 真夏、冬 → 真冬、春・秋 → 汎用の「避ける」）
   - 警告の文言を、時期ごとの理由（暑さで回復しにくい・寒さで根が傷みやすい）に合わせるため
4. **月の集合は `Months`（12ビットの値）で表す**
   - スライスと違い、コピーしても共有されないので、既定値をパッケージの変数に置いても書き換えられない。`==` で比べられる
5. **0008 の次の決定は引き継ぐ**：提案の理由は文章ではなく材料（`AfterAcclimation`、`Avoided`）で返す。南半球は6か月ずらす。探し始める日は「購入日 + 14日」と「今日」の遅いほう
   - 適期のない不正なルール（ゼロ値など）が渡された場合は、既定値を使う

## 出典（既定値）
- ミツモア「観葉植物の植え替え」：https://meetsmore.com/services/houseplants-transplant/media/180190
  - 「観葉植物の植え替えに向いている時期は、5月中旬ごろから9月中旬ごろまでです」「一般的に真夏の暑い時期には生長が鈍る植物が多いので、植え替えは避けた方が無難です」
- HugKum「観葉植物の植え替えはいつ・どうやって行う?」：https://hugkum.sho.jp/292868
  - 「植え替えは、5月〜9月、気温が15度以上になる時期が最適です」「真夏は成長も鈍くなるので、避けたほうがよいでしょう」
- いずれも一般向けの解説で、植物園や研究機関の資料ではない。より確かな出典が見つかったら見直す
