# 0008. 植え替えの時期は3つに分け、提案の理由は文章ではなく材料として返す

- 状態：採用
- 日付：2026-10-31
- 関連：タスク 3.2、`server/internal/domain/repotting.go`、要件17-2・17-3・17-7・17-8

## 決定
1. **月を「適期」「避ける時期（真夏・真冬）」「どちらでもない」の3つに分ける**
   - 要件では、適期（4〜6月・9月）と避ける時期（7〜8月・12〜2月）だけが決まっていて、3月と10〜11月はどちらでもない
   - この時期は、提案日にはしない（適期ではない）が、予定日に選ばれても警告は出さない（避ける時期ではない）
   - 3/1 に探し始めた場合、提案日は 4/1 だが「真冬を避けた」とは言わない
2. **提案の理由は、文章ではなく材料（`AfterAcclimation`、`Avoided`）として返す**
   - 画面の文言は i18n のキーから組み立てる取り決めのため、ドメインは日本語の文章を持たない
   - 例：`AfterAcclimation=true, Avoided=[midsummer]` →「慣らし期間のあと、真夏を避けた最初の適期です」
3. **南半球では、季節の判定と同じく、月を6か月ずらして判定する**
   - 要件の月は日本（北半球）を前提にしている。世帯の `hemisphere` を季節の判定と同じように扱い、考え方をそろえる
   - 月をずらす処理は `northernMonth` にまとめ、季節の判定と共通にした
4. **探し始める日は「購入日 + 14日」と「今日」の遅いほう**
   - 以前に買った植物を登録した場合でも、過去の日を提案しない

## 補足
- 慣らし期間・適期の月は、設計どおりコード内の定数とした。将来は設定テーブルへ移す
- 提案の作成・保存・採用（助言プロバイダ）は、タスク 10.1・10.2 で作る
