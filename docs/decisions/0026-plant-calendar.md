# 0026. カレンダーの予定は、今の予定日から「予定日に作業した」として周期で展開する

- 状態：採用
- 日付：2026-11-06
- 関連：タスク 9.3、`server/internal/domain/calendar.go`、`server/internal/app/calendar.go`、`server/internal/adapter/postgres/calendar.go`、`server/db/queries/calendar.sql`、要件14-1・14-3〜14-5
- 前提：設計の CalendarQuery、0020、0024、0025

## 決定
1. **`GET /plants/{id}/calendar?month=YYYY-MM` で、その月の記録・予定・メモをまとめて返す**（設計どおり）。閲覧者も見られる
   - 月を省くと、世帯のタイムゾーンでの今月にする
   - 過去の月はいくらでも戻れる（記録を見るため）。先の月は24か月までにする。予定は1回ずつ展開するので、遠い先ほど計算が長くなるため
   - 日付を選んだときの一覧（要件14-4）は、アプリがこのレスポンスを日付で絞って作る。月を移るたびに1回のリクエストで済むようにするため
2. **予定は保存せず、有効なタスク（一時停止・削除を除く）ごとに、その場で展開する**（domain の純粋な関数 `ExpandPlans`）
   - 1件目は、タスクの今の予定日。期限切れでも、その日に出す（`projected: false`）
   - 2件目からは、前の予定日に作業したものとして、その日の季節の周期を足す（完了の計算 `NextDueAfterCompletion` と同じ。`projected: true`）
   - 期限切れのタスクは、早くても今日作業するので、2件目は今日から数える。過ぎた日に見込みの予定を出さないため
   - 同じ日の予定は、タスクの作業の種類の順にする
3. **予定の項目は、タスクの全体ではなく、日付・見込みかどうか・タスクの ID・作業の種類（と作業名）だけにする**
   - 見込みの予定は、同じタスクが月に何度も出るため。タスクの詳細は、植物の詳細画面のタスクの一覧で持っている
4. **アーカイブした植物は、記録とメモだけを返し、予定は返さない**。リマインダー・今日やることと同じく、予定の対象から外すため（0017）
5. **メモの日付と月の境目は、世帯のタイムゾーンで決める**
   - メモは作成日時（`timestamptz`）しか持たないので、世帯のタイムゾーンの月初の 0 時から翌月初の 0 時まで（`[月初, 翌月初)`）で読み、日付もそのタイムゾーンで決める
   - 記録は実施日（`date`）を持つので、そのまま月の最初の日から最後の日までで読む
   - メモは、日付と本文をまとめて返す（`{date, note}`）。日付を選んだときに、メモの一覧も表示するため（要件14-4）

## 残る課題
- 作業の種類ごとの表示の区別（要件14-2）は、アプリ（タスク 17.3）で行う
- 1か月の記録とメモは件数を制限していない。実際の使い方で多くなりすぎるようなら、上限を考える
