# 0032. 完了通知は「最後の完了から60秒」でまとめ、送信と送信済みへの更新を同じトランザクションで行う

- 状態：採用
- 日付：2026-11-07
- 関連：タスク 12.2、`server/internal/job/notifications.go`、`server/internal/adapter/postgres/outbox.go`、`server/db/queries/outbox.sql`、`server/internal/domain/notification.go`、要件16・3-8
- 前提：0031（ジョブの実行基盤と FCM の送信）、0020・0022（完了・取り消しでのアウトボックスの追加と取り消し）

## 決定
1. **ジョブ `notifications` を1分ごとに実行し、アウトボックスの行を「世帯・種類・操作した人」ごとに1件の通知にまとめる**（要件16-4）
   - 送るのは、**まとまりの最後の行から60秒たったとき**（続けて完了している間は待つ）か、**最初の行から10分たったとき**（続けて完了していても送る）
   - 設計の「作成から60秒たった行をまとめる」をそのまま読むと、0秒と50秒に完了した場合、61秒の実行で0秒の分だけを送り、50秒の分は次の通知になってしまう。「短時間の複数の完了を1件に」するため、最後の完了を基準にした
   - 10分の上限は、たくさんの植物に続けて水やりしている間、通知がいつまでも届かないのを防ぐため
   - 参加の通知（`member_joined`）も同じ仕組みで送る（同じ人の参加は通常1件なので、60秒後に送る）
2. **宛先**
   - 完了通知：完了通知を受け取る設定のメンバーのうち、作業した本人を除いた人（閲覧者を含む。要件16-1〜16-3）
   - 参加の通知：オーナー。完了通知の設定には関わらず送る（要件3-8）
3. **文面はサーバーで作る**（端末の OS が表示するため）。タイトルは世帯名（複数の世帯に所属していてもわかるように）
   - 1件：「さくらさんがモンステラに水やりしました」。種類ごとに述語を変え、「その他」は作業名を使う（「モンステラの葉水をしました」）
   - 複数：「さくらさんが3件のお手入れをしました（水やり2件、肥料1件）」。内訳は作業の名前ごとに、出てきた順
   - 作業者名は、記録の時点の名前（`actor_display_name`。退会しても残る）
   - data：`type`（`completion` / `member_joined`）、`householdId`。すべて同じ植物の完了なら `plantId` も入れ、タップでその植物を開く（要件16-5）。植物が複数なら入れず、アプリは今日やること一覧を開く
4. **1つのまとまりは、1つのトランザクションで「行のロック → 送信 → 送信済みへの更新」を行う**
   - 送信と更新が同じトランザクションなので、ジョブが二重に実行されても送り直さない。送ったあとでコミットに失敗した場合だけ、もう一度送ることがある（届かないより、まれに2回届くほうを選ぶ）
   - 行は `FOR UPDATE SKIP LOCKED` で取る。取り消し（8.3）のトランザクションが行をロックしていれば飛ばし、取り消しが確定すれば送らない（要件16-6）。取り消しをやめれば、次の実行で送る。こちらが先にロックしていれば、取り消しは送り終わるのを待つ（送り始めた通知は止めない）
   - FCM への送信の間もロックを持つが、ロックするのはこのまとまりの数行だけで、ジョブは advisory lock で同時に1つしか動かない
5. **送らない行は、取り消し済み（`canceled`）にする**
   - 取り消した記録・削除した記録の行は、取り消し・削除のときに `canceled` になっている（8.3・8.4）
   - 植物の削除で記録が消えた行（`record_id` が NULL）と、参加したユーザーが退会した行は、ジョブが `canceled` にする。毎回読み直さないため
6. **FCM に届かなかったまとまりは、次の実行で送り直し、3回で諦める（`failed`）**
   - 端末ごとの失敗（`PushFailed`）では送り直さない。送り直すと、届いた端末にもう一度届くため
   - ジョブの結果は、送ったまとまりの数を `processed`、送れなかったまとまりの数を `failed` にする

## 残る課題
- 1回の実行で送るまとまりは100件まで（残りは次の実行で送る）。家族の規模では足りるが、利用者が増えたら見直す
- Cloud Scheduler のジョブ（1分ごと、`POST /internal/jobs/notifications`）の作成は、デプロイのタスクで行う
