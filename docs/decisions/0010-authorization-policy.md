# 0010. 権限はドメインのポリシー表で判定し、メンバーでなければ操作によらず 404 にする

- 状態：採用
- 日付：2026-11-01
- 関連：タスク 4.1、`server/internal/domain/role.go`、`server/internal/app/authorizer.go`、要件4-1〜4-4・13-3・20-2

## 決定
1. **ポリシー表（操作 → 許可するロール）は、`domain` の1つの map にまとめる**
   - 権限のルールを1か所で読めるようにし、ハンドラーごとに判定を書かない
   - 表にない操作・ロールは許可しない（明示的に許可したものだけを通す。fail closed）
   - テストは期待値を独立に書き、表のすべての組み合わせ（3ロール × 9操作）を確かめる。表に操作を足してテストに書き忘れたら、テストが失敗する
2. **判定は `app.Authorizer.Require(userID, householdID, action)` で行う**
   - メンバーでなければ、閲覧でも管理でも `ErrNotFound`（404）を返す。操作によって 403 と 404 を返し分けると、世帯の存在がわかってしまうため（要件4-4）
   - ロールが足りなければ `ErrForbidden`（403）を返す（要件4-3）
   - DB の障害は、403・404 にすり替えずにそのまま返す（500 になる）。障害を「権限がない」と見せると、原因に気づけないため
3. **メモの編集・削除は、`note.write` に加えて、作成者本人かオーナーであることを確かめる**（要件13-3）
   - 作成者が退会した（`author_user_id` が NULL の）メモは、オーナーだけが扱える
   - 閲覧者に変わったメンバーは、以前に自分が書いたメモでも編集できない（ロールの判定を先に行う）

## 補足
- 世帯を特定する方法（パスの `householdId`、または植物・タスクなどのリソースから引く）は、各ユースケースで作るときに決める
