# 0011. 世帯の作成は1つの SQL で行い、PATCH の「未設定に戻す」は空文字で表す

- 状態：採用
- 日付：2026-11-01
- 関連：タスク 4.2、`server/db/queries/households.sql`、`server/internal/app/household.go`、要件2-1・2-3・2-5・2-6・7-5

## 決定
1. **世帯とオーナーのメンバーシップは、`WITH ... INSERT` の1つの文で作る**
   - 片方だけができると「誰も入れない世帯」が残る。1つの文は、全体が成功するか全体が失敗するかのどちらかになる
   - トランザクションを扱う仕組み（`pgx.Tx` を Service に渡すなど）は、複数の文をまとめる必要が出たとき（完了の記録など）に作る
   - sqlc は CTE の結果を別の型（`CreateHouseholdWithOwnerRow`）にするため、`sqlcgen.Household(row)` で型を変換する。列が変われば、コンパイルエラーで気づける
2. **PATCH では、項目がなければ変えず、地域の空文字は未設定（NULL）に戻す**
   - JSON の `null` と「項目がない」を区別するには、Go では専用の型（`nullable.Nullable` など）が必要になる。世帯名は空にできないので、区別が要るのは地域だけで、空文字で十分に表せる
   - DB では未設定を NULL にそろえる（空文字を保存しない）。レスポンスでは、未設定の項目を省く
3. **権限の判定は、入力の検証より先に行う**
   - メンバーでない人が不正な入力を送ったときに 422 を返すと、世帯の存在がわかってしまう（要件4-4）
4. **NULL になりうる text の列は、sqlc で `*string` にする**（既定は `pgtype.Text`）
5. **入力の上限**：世帯名は前後の空白を除いて1〜30文字、都道府県・市区町村はそれぞれ50文字まで
   - 要件に決まりがないため、表示名と同じく、一覧や通知に収まる長さにした。地域は自由入力とし、都道府県の一覧による検証はしない（天気の助言を作るフェーズ2で見直す）

## 補足
- 世帯の変更をほかのメンバーに届ける（`version` を増やし、変更を通知する）処理は、リアルタイム同期のタスク 11.1 で加える
- `timeZone` と `hemisphere` は、今は初期値（`Asia/Tokyo`、北半球）のまま返すだけで、変更はできない
