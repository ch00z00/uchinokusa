# 0021. スキップは予定の回を進めず、確認日を「手で決めた予定日」として扱う

- 状態：採用
- 日付：2026-11-05
- 関連：タスク 8.2、`server/internal/domain/care_record.go`、`server/internal/app/care_record.go`、`server/internal/adapter/postgres/care_records.go`、要件10-6〜10-8・16-7・19-7
- 前提：設計の「次回予定の計算ルール」、0018、0019、0020

## 決定
1. **スキップ（`POST /tasks/{id}/skips`）は、完了と同じ形の1つのトランザクションで行う**
   - タスクの行ロック → 予定の回の確認 → 記録（`outcome = skipped`）の作成 → タスクの次回予定を確認日にする
   - 完了通知のアウトボックスには入れない（要件16-7）
   - 取り消し（8.3）で戻せるよう、記録する前の予定日と回（`prev_next_due_on`・`prev_cycle_seq`）を保存する
2. **予定の回は進めない**。スキップした回に、あとから完了できる。同じ回を続けてスキップすること（翌日も土が湿っていた場合など）もできる
3. **送った `cycleSeq` がタスクの今の回と違えば、前でも後でも `409 stale_cycle`**
   - スキップは回を進めないので、今の回以外へのスキップは、どれもアプリの表示が古いことを表す
   - 別のメンバーが先に完了していた場合も `stale_cycle` になる。アプリはタスクを取り直して、完了済みを表示する
4. **確認日は、翌日以降に限る**（要件10-8）。省くと、世帯のタイムゾーンでの翌日にする（0020 の「今日」と同じ決め方）。今日以前にすると、スキップしたタスクが今日やることに残ってしまうため `422`（`fields.recheckOn = invalid`）にする
5. **確認日は、手で変えた予定日と同じく `due_overridden` を立てる**
   - 季節の切り替えのジョブ（12.4）が「最終完了日 + 新しい周期」で計算し直すと、ユーザーが選んだ確認日が動いてしまうため
   - 次の完了で印が外れ、周期からの計算に戻る（0020）
6. **理由は、決まった値（`soil_wet`・`bad_weather`・`plant_weak`・`other`）と自由入力（200文字まで）に分けて保存する**（要件10-7・19-7）
   - 決まった値は、将来の助言の改善で集計に使える形にするため
   - 理由は任意。自由入力は `other` のときだけ受け付け、ほかの理由や理由なしに添えると `422`（`fields.reasonText = invalid`）にする。送った文を黙って捨てないようにするため
7. **一時停止中のタスクもスキップでき、一時停止のままにする**（0020 の完了と同じ扱い）。再開すると、0019 の規則で次回予定が決まる
8. 記録の取得（API の `CareRecord`）には、スキップのときだけ `skipReason`・`skipReasonText`・`recheckOn` が入る

## 残る課題
- スキップの理由を助言に使う処理は、助言のタスク（10.x）とフェーズ2以降で扱う
- スキップの変更の通知（リアルタイムの配信）は、タスク 11.x で加える
