# ヘッダーのボタンが、押しても反応しないことがある

- 日付：2026-11-24
- 場所：アプリ（iOS 26）。今日の画面のヘッダーの「選択」「キャンセル」（タスク 17.2c）
- 状態：直した（f29622f）。ユーザーの確認待ち
- キーワード：React Native、Expo Router、react-native-screens、UIKit のヒットテスト、hitSlop、タップ領域 44pt

## 30秒で話すなら

> ヘッダーの文字のボタンが、ときどき押しても反応しない不具合がありました。シミュレーターのせいと思われていましたが、react-native-screens のネイティブのコードを読んで、原因を特定しました。iOS のネイティブのヘッダーに埋め込んだ React Native のビューは、その枠の外のタッチを受け付けません。そのため、`hitSlop` で押せる範囲を広げたつもりでも効いておらず、実際に押せるのは高さ 22pt ほどの文字の部分だけでした。対策として、`hitSlop` に頼らず、ビューの枠そのものを 44pt 以上にしました。ヘッダーに置く部品で共通に使えるように、フックにまとめています。同じ問題が、ほかの画面の3か所にもあったので、まとめて直しました。

## 起きたこと

- 今日の画面で、ヘッダーの右の「選択」や、選択モードの「キャンセル」を押しても、ときどき反応しなかった
- ユーザーは「シミュレーターのせいかも」と言っていた。ほかの操作には問題がなかった

## 調べた順番

1. **部品の作りを見る**：`HeaderTextButton` は、文字を `Pressable` で包み、`hitSlop={12}` で押せる範囲を周りに広げていた。数字のうえでは、押せる範囲は約 46pt あるはずだった
2. **置き方を見る**：iOS 26 では、ヘッダーの項目を `unstable_headerRightItems` の `type: 'custom'` で置いている。これは、React Native のビューを、UIKit の `UIBarButtonItem` の `customView` として埋め込む仕組み
3. **ライブラリのネイティブのコードを読む**：react-native-screens の `RNSScreenStackHeaderSubview.mm`（`getUIBarButtonItem`）を読んだ
   - iOS 26 では、React Native のビューを、同じ大きさの入れ物のビュー（最低幅 36pt）に入れて、`customView` にしている
   - UIKit のヒットテスト（どのビューがタッチを受けるかを決める処理）は、親のビューの枠の外のタッチを、子に渡さない
   - `hitSlop` は React Native の中での当たり判定を広げるだけで、UIKit が枠の外のタッチを React Native に渡さなければ効かない
4. **結論**：押せる範囲は、文字そのものの範囲（「選択」なら約 36×22pt）だけだった。Apple のガイドラインの 44pt の半分ほどの高さしかなく、少し外すと反応しない

## 直したこと

- `useHeaderHitArea()` を足した。ビューの枠そのものを、高さ・幅とも 44pt（デザインのトークンの `size.tapMin`）以上にし、文字を中央に置くスタイルを返す
- 同じ作りだった3か所で使った
  - `HeaderTextButton`（「選択」「キャンセル」「編集」「追加」など）
  - 世帯名の切り替え（`HouseholdSwitcher`）
  - QR 読み取りの画面の「キャンセル」
- 見た目はほとんど変わらない（文字の位置が数 pt 内側に寄る程度）
- デザインの基礎（`docs/design/foundations.md`）に、「ヘッダーに置く自作の部品は、hitSlop ではなく枠そのものを 44pt 以上にする」と決まりを書いた。次にヘッダーに部品を足すときも、同じ間違いをしないため

## 残った可能性（未確認）

- react-native-screens は、ヘッダーの項目を差し替えるとき、古いビューをいったん静止画（スナップショット）に置き換える（`RNSScreenStackHeaderConfig.mm` の `replaceNavigationBarViewsWithSnapshotOfSubview`）
- 選択モードの出入りでヘッダーの左右がまるごと入れ替わるので、その直後の一瞬に押すと反応しない可能性がある
- 今回の修正のあとも反応しないことが残れば、ヘッダーの項目を作り直さずに中身だけ変える形にする

## 学んだこと

- **抽象化の境界をまたぐと、前提が変わる**：`hitSlop` は React Native の中では効くが、ネイティブの部品に埋め込むと、UIKit のルールが先に効く。「React Native の部品だから、React Native の設定が効く」とは限らない
- **「環境のせい」で片付けず、仕組みから確かめる**：シミュレーターのせいに見えたが、実機でも起きる作りの問題だった。ライブラリのネイティブのコードまで読むと、推測ではなく根拠をもって説明できた
- **一か所の不具合は、同じ作りの場所を探す**：原因が「作り方」にあるとわかったので、同じ作り方をしている場所を検索し、まだ報告されていない2か所も直した
- **直し方を決まりにする**：コードを直すだけでなく、デザインの基礎の文書に決まりとして残し、再発を防いだ

## 面接で聞かれそうなこと

- **なぜ hitSlop が効かないのか？** → UIKit のヒットテストは、親の枠の外のタッチを子に渡さない。`hitSlop` は React Native のタッチの仕組みの中の設定で、そもそもタッチが React Native に届かなければ効かない
- **なぜ 44pt なのか？** → Apple の Human Interface Guidelines が勧める、押せる領域の最小の大きさ。プロジェクトでは `size.tapMin` というトークンにしている
- **ほかの直し方は？** → ネイティブのボタンの項目（`type: 'button'`）を使う方法もある。OS が押せる範囲を面倒みてくれるが、文字の見た目（色・太さ）を世帯名とそろえる自由が減るので、今回は自作の部品のまま枠を広げた
